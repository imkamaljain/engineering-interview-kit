## Scenario

> **Your application consumes too much browser memory. How would you investigate?**

When an app consumes excessive RAM, browser performance stutters, mobile devices force-close tabs, and battery drains rapidly. Interviewers look for methodical forensic skills.

## Fast Revision (10-Second Recall)

- **First Move:** Open **Chrome Task Manager (`Shift + Esc`)** to inspect "Memory Footprint" and "JavaScript Memory" in real time.
- **Four Potential Sources:**
- 1. **Unbounded In-Memory Data:** Caching 100,000 JSON records in state without eviction.
- 2. **Bloated DOM Tree:** >10,000 DOM elements on a single page.
- 3. **Large Media & Canvas:** High-resolution uncompressed canvas graphics or base64 data URLs in state.
- 4. **Accumulating Closures / Leaks:** Memory steadily grows over time without recovering after GC.

## The 30-Second Spoken Script

If asked this in an interview, deliver this structured response:

> *I investigate excessive browser memory systematically starting from the highest level of abstraction down to specific object retainers.*
>
> *First, I open Chrome Task Manager (Shift + Esc) to differentiate between total browser tab memory and JS heap memory. If JS memory is low but tab memory is huge, the problem is likely unoptimized DOM nodes, images, or WebGL/Canvas contexts.*
>
> *If JS heap memory is the culprit, I open the DevTools Performance panel and record a timeline with the 'Memory' checkbox enabled. This produces a saw-tooth graph. If the trough of the saw-tooth rises steadily and never returns to baseline after garbage collection, we have an active leak.*
>
> *Next, I use the Memory tab's 'Allocation instrumentation on timeline' to see real-time object creation spikes. I look for massive JSON payloads cached in global state, duplicate strings, and detached DOM trees.*
>
> *Once the source is identified, I implement LRU caching, windowing, and memory eviction to keep memory under a strict 150MB budget.*

## Root Causes & Solutions Matrix

| Suspected Layer | Symptoms & Evidence | Immediate Resolution |
| :--- | :--- | :--- |
| **Massive Global Cache** | Storing all historical API responses in Redux without an eviction limit. | Implement an LRU cache (e.g. `quick-lru`) capping entries to the latest 50. |
| **Base64 Image Strings** | Storing 20MB raw base64 images in state or localStorage. | Use `URL.createObjectURL(file)` or upload directly to S3 and store lightweight URLs. |
| **Excessive DOM Elements** | `document.querySelectorAll("*").length` reports over 25,000 nodes. | Enforce DOM virtualization; keep active DOM nodes below 1,500. |
| **WebGL / HTML5 Canvas** | Creating new canvas rendering contexts on every mount without clearing. | Explicitly resize canvas to 0x0 and clear contexts before unmounting. |

## Practical Debugging Commands & Code

### Auditing DOM Node Counts & Capping In-Memory Caches
```typescript
// 1. Quick Console Script to Audit DOM Bloat
function auditDOMSize() {
  const totalNodes = document.querySelectorAll('*').length;
  console.log(`Total DOM Nodes: ${totalNodes}`);
  if (totalNodes > 1500) {
    console.warn('⚠️ Warning: DOM size exceeds recommended budget of 1500 nodes!');
  }
}

// 2. Memory-Safe LRU Cache for API Responses
export class BoundedMemoryCache<T> {
  private maxSize: number;
  private cache: Map<string, T>;

  constructor(maxSize = 50) {
    this.maxSize = maxSize;
    this.cache = new Map();
  }

  get(key: string): T | undefined {
    if (!this.cache.has(key)) return undefined;
    // Refresh key order (MRU)
    const val = this.cache.get(key)!;
    this.cache.delete(key);
    this.cache.set(key, val);
    return val;
  }

  set(key: string, value: T): void {
    if (this.cache.has(key)) {
      this.cache.delete(key);
    } else if (this.cache.size >= this.maxSize) {
      // Evict oldest item (First item in Map iterator)
      const oldestKey = this.cache.keys().next().value;
      if (oldestKey) this.cache.delete(oldestKey);
    }
    this.cache.set(key, value);
  }
}
```

## Prevention & Senior Best Practices

1. **Enforce DOM Node Limits:** Lighthouse flags pages with more than 1,400 DOM nodes; treat high node counts as architectural bugs.
2. **Avoid Storing Binary Data in React State:** Handle file uploads via direct streams or `FormData` instead of reading entire files into memory as strings.
3. **Monitor performance.memory in Staging:** Periodically log `performance.memory.usedJSHeapSize` during automated QA smoke tests.
