## Concept

In computer science, a **String** is not a fundamental, primitive data type. 
A String is actually just an **Array of Characters**.

Because strings are just arrays under the hood, almost every single algorithmic technique you learned for Arrays (Two Pointers, Sliding Window, Hash Maps) applies directly to Strings. 

## Memory and Immutability

The most critical thing to understand about strings in modern high-level languages (like JavaScript, Python, and Java) is that **Strings are Immutable**.

```typescript
let name = "Apple";
name[0] = "B"; // Trying to change it to "Bpple"
console.log(name); // Output: "Apple" (It silently failed!)
```

When you create a string in memory, it is locked forever. 
If you want to modify a string, you cannot change the existing characters in place. You must ask the CPU to allocate a brand new block of memory, copy the old characters over, apply your changes, and point your variable to the new memory block.

### The Immutability Trap
If you try to build a massive string inside a `for` loop by concatenating characters:
```typescript
let result = "";
for (let char of massiveArray) {
    result += char; // DANGER!
}
```
In older languages (like Java before `StringBuilder`), this was an **$O(N^2)$** operation! Every single time you added a character, the CPU had to copy the entire existing string into a new, larger memory slot. 
*(Note: Modern JavaScript engines like V8 heavily optimize string concatenation under the hood using "Ropes", so `+=` is generally safe in JS, but building an array and calling `.join("")` remains the safest, most universally accepted pattern in interviews).*

## Encoding: ASCII vs Unicode

A computer processor does not understand the letter `A`. It only understands numbers.
To fix this, engineers created mapping tables.

1. **ASCII (The Old Way):** An 8-bit table. `A` maps to the number `65`. `a` maps to `97`. `0` maps to `48`. Because 8 bits only hold 256 unique numbers, ASCII only supports standard English characters.
2. **Unicode (The Modern Way):** A massive table that holds over 140,000 characters, including Chinese Kanji, Arabic, and emojis. UTF-8 is the most common encoding format for Unicode.

## Interview Strategy

When faced with a String problem, look for these patterns:
1. **Anagrams / Permutations:** Use a Hash Map (Frequency Counter) or sort both strings and compare them.
2. **Palindromes:** Use Two Pointers (Left and Right squeezing inward).
3. **Substring Search:** Use a Sliding Window.
4. **Parsing / Evaluation:** Use a Stack (e.g., matching parentheses, evaluating math expressions).

## Interview Questions

**Q: A problem asks you to reverse a string in-place to achieve $O(1)$ space complexity. Can you do this in JavaScript or Python?**
**A:** No. Because strings are immutable in JavaScript and Python, you mathematically cannot reverse them in-place. You are forced to convert the string into an Array first (`s.split("")`), reverse the array, and join it back together. Converting a string to an array automatically consumes **$O(N)$ extra space**. You must explicitly tell the interviewer: *"In a language like C or C++, I could do this in $O(1)$ space using Two Pointers to swap the characters directly in memory. But because JS strings are immutable, I must use $O(N)$ space to create a mutable array."*

**Q: You need to compare if two strings are identical. Does this take $O(1)$ time?**
**A:** No, string comparison is an **$O(N)$** operation. The CPU has to start at index 0 and compare `stringA[0] === stringB[0]`, then move to index 1, etc., until it reaches the end of the strings. Comparing massive strings takes linear time.
