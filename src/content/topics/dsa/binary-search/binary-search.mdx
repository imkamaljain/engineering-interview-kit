## Concept

If you are looking for the word "Zebra" in a physical dictionary, you don't start at page 1 and read every single word. You open the book exactly to the middle. You see the letter "M". Because "Z" comes after "M", you instantly rip the book in half, throw away the first half, and repeat the process on the second half.

This is **Binary Search**. It mathematically requires the data to be **Sorted**.
Every time it makes a decision, it permanently eliminates exactly half of the remaining search space.

## The Mental Model

`Array: [1, 3, 5, 7, 9, 11, 15]`. Target: `11`.
1. `Left` pointer at `0`, `Right` pointer at `6`.
2. Find `Mid`: `(0 + 6) / 2 = 3`. The value at index 3 is `7`.
3. `11` is greater than `7`. 
4. Move `Left` pointer to `Mid + 1` (Index 4). The new search space is `[9, 11, 15]`.
5. Repeat.

## Implementation

The standard Binary Search algorithm is relatively simple, but getting the `+1` and `-1` edge cases right is notorious for causing infinite loops in interviews.

```typescript
// Time Complexity: O(log N)
// Space Complexity: O(1)

function binarySearch(nums: number[], target: number): number {
    let left = 0;
    let right = nums.length - 1;

    // Use <= so we actually check the final remaining element when Left and Right collide!
    while (left <= right) {
        
        // Find the middle index.
        // Math.floor is critical in JS because division returns decimals!
        const mid = Math.floor((left + right) / 2);

        if (nums[mid] === target) {
            return mid; // Found it!
        } else if (nums[mid] < target) {
            // Target is larger. It must be in the right half.
            // Move the left boundary PAST the mid point.
            left = mid + 1;
        } else {
            // Target is smaller. It must be in the left half.
            // Move the right boundary BEFORE the mid point.
            right = mid - 1;
        }
    }

    return -1; // Target does not exist in the array
}
```

## The Integer Overflow Trap

Look at this line: `const mid = Math.floor((left + right) / 2);`

In JavaScript, this is perfectly safe because JS numbers are Double Precision Floats that can hold up to 9 quadrillion.
However, in languages with strict 32-bit Integers (like Java, C++, or Go), if `left` is 2 billion, and `right` is 2 billion, adding them together equals 4 billion. This exceeds the 32-bit integer maximum (2.14 billion), causing an **Integer Overflow**. The number wraps around to negative 2 billion, crashing your code.

To prevent this, you must calculate the middle without addition:
`const mid = left + Math.floor((right - left) / 2);`
This calculates the *distance* between the two pointers, halves it, and adds it to the left base, perfectly preventing the overflow.
**Always use this formula in technical interviews to show seniority.**

## Interview Strategy

Binary Search is heavily tested in FAANG interviews, but they rarely ask you to just "Find the number in the array."

The trick to advanced Binary Search is recognizing that the "Array" doesn't have to be physical numbers in memory. The array can be a **Range of Possible Answers** (e.g., `Left = 1`, `Right = 1000`). If you have a helper function `isValid(mid)` that evaluates a guess in $O(N)$ time, you can binary search the absolute optimal answer in $O(N \log M)$ time! This is called "Binary Search on Answer".

## Interview Questions

**Q: A developer uses recursion to write Binary Search. Is this optimal?**
**A:** Recursion is mathematically elegant, but suboptimal for Binary Search. The recursive version takes $O(\log N)$ Space Complexity because of the Call Stack frames. The standard iterative `while` loop version is significantly better because it achieves $O(1)$ Space Complexity while retaining the exact same $O(\log N)$ Time Complexity.

**Q: Why do we use `left <= right` instead of `left < right`?**
**A:** If you use `left < right`, the `while` loop will instantly terminate the moment the `Left` and `Right` pointers land on the exact same index. The algorithm will completely fail to evaluate that final cell. If the target happens to be sitting in that exact final cell, the algorithm will wrongly return `-1`. You must use `<=` so the loop runs one final time to check the collision point.
