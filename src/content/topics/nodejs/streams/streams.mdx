## TL;DR

**Streams** are a way to process reading and writing of data piece-by-piece (chunks) rather than loading everything into memory at once. They are essential for performance when dealing with large files or network requests.

## Mental Model

## How It Works

Instead of waiting for an entire file to load into RAM (which could crash the server if the file is larger than available memory), streams process data in small **buffers** (default is usually 64kb). 

There are four main types of streams in Node.js:
1.  **Readable**: For reading data (e.g., `fs.createReadStream`).
2.  **Writable**: For writing data (e.g., `fs.createWriteStream`).
3.  **Duplex**: Can both read and write (e.g., TCP sockets).
4.  **Transform**: A Duplex stream that modifies data as it passes through (e.g., `zlib.createGzip`).

## Example

```javascript
const fs = require('fs');

// BAD: Loads entire file into memory
fs.readFile('largeVideo.mp4', (err, data) => {
    // res.send(data); 
});

// GOOD: Streams file chunk by chunk, keeping memory usage very low
const readStream = fs.createReadStream('largeVideo.mp4');
readStream.pipe(res); // Pipes data directly to the HTTP response
```

## Common Interview Questions

### What is the `.pipe()` method?
`pipe()` is a method on Readable streams that attaches it to a Writable stream. It automatically handles the flow of data and manages **backpressure**, ensuring the Readable stream doesn't overwhelm the Writable stream if it's slower.

### Can you give an example of a built-in Node.js stream?
`process.stdout` is a Writable stream, `process.stdin` is a Readable stream. An HTTP Request object (`req`) is a Readable stream, and the Response object (`res`) is a Writable stream.
