## TL;DR

Streams are collections of data that might not be available all at once and don't have to fit in memory. They allow you to process data chunk-by-chunk, making them essential for handling large files or continuous network data.

## Mental Model

```mermaid
flowchart LR
    Source[(Large File\n10 GB)]
    Readable["Readable Stream\n(Reads 64KB chunks)"]
    Transform["Transform Stream\n(e.g., Compress/Encrypt)"]
    Writable["Writable Stream\n(Writes to network/disk)"]
    Dest(("Client\nNetwork"))
    
    Source -->|chunk| Readable
    Readable -->|.pipe()| Transform
    Transform -->|.pipe()| Writable
    Writable -->|chunk| Dest
```

## Example: Reading a huge file

```javascript
// BAD: Reads the entire 10GB file into RAM. App crashes!
const fs = require('fs');
const http = require('http');

http.createServer((req, res) => {
    fs.readFile('massive-video.mp4', (err, data) => {
        res.end(data); 
    });
}).listen(3000);

// GOOD: Streams it piece by piece. Memory footprint stays < 50MB.
http.createServer((req, res) => {
    const stream = fs.createReadStream('massive-video.mp4');
    stream.pipe(res); 
}).listen(3001);
```

## Types of Streams

1. **Readable**: Streams you can read data from (e.g., `fs.createReadStream()`, `process.stdin`, `http.IncomingMessage`).
2. **Writable**: Streams you can write data to (e.g., `fs.createWriteStream()`, `process.stdout`, `http.ServerResponse`).
3. **Duplex**: Streams that are both Readable and Writable (e.g., TCP sockets).
4. **Transform**: A type of Duplex stream that modifies or transforms the data as it is written and read (e.g., `zlib.createGzip()`).

## Interview Questions

### What is `.pipe()`?
`.pipe()` is a method used to connect a Readable stream to a Writable stream. It automatically handles the flow of data, ensuring the Writable stream isn't overwhelmed by a fast Readable stream (this is called handling **Backpressure**).

### What happens if the Readable stream is much faster than the Writable stream?
This causes **Backpressure**. The Writable stream's internal buffer will fill up. When using `.pipe()`, Node.js automatically detects this, pauses the Readable stream until the Writable stream has drained its buffer, and then resumes it. If you build your own streams using `.on('data')`, you must manage this manually using `.pause()` and `.resume()`.

## Common Gotchas

*   **Error Handling in `.pipe()`**: If an error occurs in the Readable stream, the Writable stream is NOT automatically closed, and vice versa. You must attach `.on('error')` handlers to *every* stream in a pipeline, or use the newer `stream.pipeline()` utility method which automatically cleans up broken streams.

## Remember

> Streams are arrays over time. Use them whenever data is large, infinite, or arriving slowly.
