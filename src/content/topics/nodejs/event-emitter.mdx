## TL;DR

The `EventEmitter` class is a core module in Node.js that implements the **Observer Pattern**. It allows objects to emit named events that cause previously registered "listener" functions to be called.

## Mental Model

```mermaid

    Publisher["Publisher\n(EventEmitter)"]

    Listener1["Listener 1\n(console.log)"]

```

## Example

```javascript
const EventEmitter = require('events');

class PaymentProcessor extends EventEmitter {
    process(amount) {
        console.log(`Processing payment of $${amount}`);
        
        // Emits an event with data
        this.emit('success', { amount, id: 123 });
    }
}

const processor = new PaymentProcessor();

// Subscribe to the event
processor.on('success', (data) => {
    console.log(`Email Sent: Receipt for $${data.amount}`);
});

// Another subscriber
processor.once('success', () => {
    console.log("Analytics: First successful payment recorded.");
});

processor.process(50);
```

## How It Works

1.  **`on(event, listener)`**: Adds a callback function to the array of listeners for the specified event name.
2.  **`emit(event, ...args)`**: Synchronously calls all listeners registered for the event, passing the supplied arguments to each.
3.  **`once(event, listener)`**: Adds a listener that will be executed *only the next time* the event is emitted, then it is removed.

## Interview Questions

### Is `EventEmitter` synchronous or asynchronous?
It is **synchronous**. When you call `emit()`, it loops through and executes all the listener callbacks immediately, blocking the thread until they finish. If you need it to be asynchronous, you must explicitly wrap your listener code in `setImmediate()` or `process.nextTick()`.

### How do you prevent memory leaks with EventEmitters?
If you add an `.on()` listener to a global or long-lived object (like `process` or a Server) and forget to call `.removeListener()`, it creates a memory leak. 
Node.js prints a warning if more than 10 listeners are added to a single event (can be changed via `setMaxListeners()`). Always clean up listeners on component unmount or when no longer needed!

## Common Gotchas

*   **Unhandled Error Events**: If an EventEmitter emits an `'error'` event and there is no listener attached to `'error'`, Node.js will automatically throw the error and crash the application. Always attach an `.on('error', ...)` listener to streams, servers, and custom emitters.

## Remember

> EventEmitters power almost all of Node.js's async architecture (HTTP servers, streams, file systems). They are synchronous by default!
