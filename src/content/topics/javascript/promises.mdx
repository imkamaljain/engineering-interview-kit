## TL;DR

A Promise is an object representing the eventual completion (or failure) of an asynchronous operation and its resulting value. It avoids "callback hell" by allowing you to chain `.then()` and `.catch()` blocks.

## Mental Model

```mermaid
flowchart LR
    Pending((Pending))
    Fulfilled((Fulfilled / Resolved))
    Rejected((Rejected))
    
    Pending --> |resolve(value)| Fulfilled
    Pending --> |reject(error)| Rejected
```
*Note: Once a Promise is fulfilled or rejected, its state is **settled** and cannot change.*

## Example

```javascript
const fetchUser = new Promise((resolve, reject) => {
    setTimeout(() => {
        const success = true;
        if (success) {
            resolve({ id: 1, name: "Alice" });
        } else {
            reject("Failed to fetch user");
        }
    }, 1000);
});

fetchUser
    .then(user => console.log(user.name))
    .catch(error => console.error(error))
    .finally(() => console.log("Operation finished."));
```

## Combinators (Comparison)

| Method               | Behavior                                                     | Use Case                                  |
| -------------------- | ------------------------------------------------------------ | ----------------------------------------- |
| **`Promise.all`**    | Fails fast. Resolves when ALL pass. Rejects if ANY fail.     | Fetching data where every piece is required |
| **`Promise.allSettled`** | Waits for all. Never rejects. Returns array of objects with status/value/reason. | Executing independent tasks, logging failures |
| **`Promise.race`**   | First settled. Returns result of the FIRST Promise to finish (resolve or reject). | Implementing a timeout for an API call    |
| **`Promise.any`**    | First fulfilled. Returns FIRST successful Promise. Rejects only if ALL fail. | Querying multiple CDNs, taking fastest successful |

## Interview Questions

### What is the difference between `.then(onSuccess, onError)` and `.then(onSuccess).catch(onError)`?
If `onSuccess` throws an error in `.then(onSuccess, onError)`, the `onError` handler in the *same* `.then()` block **will not** catch it. 
However, `.then(onSuccess).catch(onError)` **will** catch an error thrown inside `onSuccess`.

### How can you convert a callback-based function to a Promise?
By wrapping it in a `new Promise` constructor.
```javascript
const readFilePromise = (path) => new Promise((resolve, reject) => {
    fs.readFile(path, (err, data) => {
        if (err) reject(err);
        else resolve(data);
    });
});
```

## Common Gotchas

*   **Forgetting to return**: If you don't `return` a value or Promise inside a `.then()` block, the next `.then()` receives `undefined`.
*   **Swallowing Errors**: If you don't add a `.catch()` block at the end of a chain, an error might be silently unhandled.

## Remember

> A Promise is a placeholder for a value that you don't have yet. It guarantees you will eventually get either that value or a reason why it failed.
