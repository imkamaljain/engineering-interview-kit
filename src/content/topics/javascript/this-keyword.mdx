## TL;DR

In JavaScript, `this` refers to the object that is executing the current function. Unlike other languages, its value is determined by **how** a function is called, not where it is defined (with the exception of arrow functions).

## Mental Model

```mermaid
flowchart TD
    Call[Function is Called]
    
    Call --> IsArrow{Is it an arrow function?}
    
    IsArrow -->|Yes| Lexical[Inherits 'this' from surrounding lexical scope]
    
    IsArrow -->|No| HowCalled{How was it called?}
    
    HowCalled -->|Method: obj.func()| Method[this = obj]
    HowCalled -->|Standalone: func()| Standalone[this = window / undefined in strict mode]
    HowCalled -->|Constructor: new func()| Constructor[this = newly created instance]
    HowCalled -->|Explicit: func.call(obj)| Explicit[this = obj]
```

## Example

```javascript
const user = {
    name: "Alice",
    regularMethod: function() {
        console.log(this.name);
    },
    arrowMethod: () => {
        console.log(this.name);
    }
};

user.regularMethod(); // "Alice"
user.arrowMethod();   // undefined (inherits 'this' from global scope)

// Context loss
const detached = user.regularMethod;
detached(); // undefined (called standalone)
```

## How It Works

1. **Implicit Binding**: When a function is called as a method of an object (`user.regularMethod()`), `this` points to the object left of the dot.
2. **Default Binding**: When a function is called standalone (`detached()`), `this` points to the global object (`window` in browsers, `global` in Node). In strict mode, it is `undefined`.
3. **Explicit Binding**: Using `call()`, `apply()`, or `bind()` allows you to explicitly set what `this` should point to.
4. **New Binding**: When a function is invoked with the `new` keyword, `this` points to the newly constructed object.
5. **Lexical Binding (Arrow Functions)**: Arrow functions do not have their own `this`. They capture the `this` value of the enclosing execution context at the time they are created.

## Interview Questions

### How do you fix context loss in a callback?
If you pass a method as a callback (e.g., `setTimeout(user.regularMethod, 1000)`), it loses its context because it's called standalone later.
**Fixes:**
1. Wrap it in a function: `setTimeout(() => user.regularMethod(), 1000)`
2. Use `.bind()`: `setTimeout(user.regularMethod.bind(user), 1000)`

### What is the difference between `call`, `apply`, and `bind`?
- **`call(thisArg, arg1, arg2)`**: Invokes the function immediately with arguments passed individually.
- **`apply(thisArg, [argsArray])`**: Invokes the function immediately with arguments passed as an array.
- **`bind(thisArg, arg1, arg2)`**: Returns a *new function* with `this` permanently bound. It does not execute immediately.

## Common Gotchas

*   **Using Arrow Functions as Methods**: Arrow functions as object methods inherit `this` from the global scope, not the object. They are bad choices for methods that need to access the object's properties.
*   **Event Listeners**: In standard DOM event listeners (`element.addEventListener`), `this` points to the element that fired the event, *unless* you pass an arrow function.

## Remember

> For regular functions, `this` is about **who called it**. For arrow functions, `this` is about **where it was born**.
