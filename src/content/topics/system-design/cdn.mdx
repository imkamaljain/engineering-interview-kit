## TL;DR

A Content Delivery Network (CDN) is a globally distributed group of servers that caches static content (images, videos, HTML/CSS/JS) close to the user's geographical location, drastically reducing latency and offloading traffic from your origin server.

## Mental Model

```mermaid
flowchart LR
    User["User (Tokyo)"]
    Origin["Origin Server\n(New York)"]
    
    Edge1["CDN Edge Server\n(Tokyo)"]
    Edge2["CDN Edge Server\n(London)"]
    
    User -->|1. Request Image| Edge1
    Edge1 -. "2. Cache Miss" .-> Origin
    Origin -. "3. Return Image" .-> Edge1
    Edge1 -->|4. Return Image\n(Now Cached)| User
```
*Next time a user in Tokyo requests the image, Edge1 returns it instantly without contacting New York.*

## Types of CDN Routing

1. **Push CDN**: You actively upload your static assets to the CDN when you deploy your site. The CDN takes responsibility for distributing them.
2. **Pull CDN**: You leave assets on your origin server. The first time a user requests an asset, the CDN "pulls" it from the origin, caches it, and serves it. Subsequent requests hit the cache. (Most common for web apps).

## Interview Questions

### How does a CDN know which Edge Server is closest to the user?
Through **GeoDNS** or **Anycast Routing**. When the user resolves the CDN's domain name, the DNS server looks at the user's IP address and returns the IP address of the edge server geographically closest to them.

### What happens when an asset is updated on the origin server?
If you update a logo but keep the filename `logo.png`, the CDN will continue serving the old cached version until its TTL expires. 
To fix this, you use **Cache Busting**: appending a unique hash to the filename when you deploy (e.g., `logo.a8f9c.png`). The CDN sees this as a brand-new file and pulls the new version.

### Can CDNs serve dynamic content?
Traditionally no, but modern CDNs (like Cloudflare or AWS CloudFront) support **Edge Computing** (e.g., Cloudflare Workers). This allows you to run lightweight JavaScript/WebAssembly functions directly on the edge server to personalize requests, authenticate users, or modify headers before they hit the origin.

## Remember

> The speed of light is a hard limit. No matter how fast your New York server is, a request from Tokyo will always take ~200ms. A CDN solves the physics problem by moving the data to Tokyo.
