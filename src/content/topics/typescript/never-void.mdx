## TL;DR

- **`void`**: Used when a function successfully finishes executing, but returns absolutely nothing (or `undefined`).
- **`never`**: Used when a function **will never finish executing** (because it throws an error or has an infinite loop). 

## Mental Model

```mermaid
flowchart LR
    Func["Function Call"]
    
    Func -->|Completes normally| Void["void\n(Returns undefined)"]
    Func -. "Throws Error or Infinite Loop" .x Never["never\n(Code after this is unreachable)"]
```

## Example

```typescript
// --- VOID ---
// This function finishes successfully. It just doesn't return a value.
function logMessage(msg: string): void {
    console.log(msg);
    // implicitly returns undefined
}

// --- NEVER ---
// This function NEVER reaches the end of its execution context.
function throwError(msg: string): never {
    throw new Error(msg);
}

// Infinite loops also return never
function keepRunning(): never {
    while (true) {
        console.log("Running...");
    }
}
```

## Advanced Use Cases for `never`

`never` represents an "impossible state" in TypeScript's type system. It is the lowest type in the hierarchy (the bottom type).

### Exhaustiveness Checking
You can use `never` to ensure a `switch` statement handles *every* possible case of a union.

```typescript
type Status = "Pending" | "Done";

function handleStatus(status: Status) {
    switch (status) {
        case "Pending": break;
        case "Done": break;
        default:
            // If we add "Failed" to the Status union but forget to add a case for it,
            // TypeScript will throw an error here because 'status' is not 'never'.
            const exhaustiveCheck: never = status;
            return exhaustiveCheck;
    }
}
```

## Interview Questions

### Can you assign `undefined` to a `never` type?
**No**. `never` accepts absolutely no values, not even `any` or `undefined`. Conversely, you *can* assign `undefined` to a `void` type.

### What does it mean if a variable's type is inferred as `never`?
It usually means TypeScript has narrowed a type so much that there are no possible values left. For example, if a variable is `string & number` (which is impossible), TypeScript will infer its type as `never`.

## Remember

> `void` says: "I will finish, but I'll give you nothing."
> `never` says: "I will not finish."
