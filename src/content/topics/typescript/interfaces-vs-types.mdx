## TL;DR

`interface` and `type` are mostly interchangeable for defining object shapes. The key difference is that **Interfaces support declaration merging**, while **Types support unions, intersections, and mapped types**.

## Mental Model

*   **Interface**: Think of it as an open, extendable contract for an object (like OOP classes).
*   **Type Alias**: Think of it as a strict mathematical definition that can describe *anything* (primitives, unions, exact shapes), but once defined, it is closed.

## Example

```typescript
// --- INTERFACES ---
interface User {
    name: string;
}

// Declaration Merging (Allowed)
interface User {
    age: number; 
}
// User is now { name: string, age: number }

// --- TYPES ---
type Animal = {
    species: string;
};

// Error: Duplicate identifier 'Animal'
// type Animal = { weight: number }; 

// Types can do Unions (Interfaces cannot)
type Status = "Pending" | "Approved" | "Rejected";
```

## How It Works

1.  **Extending**:
    *   Interfaces use `extends`: `interface Dog extends Animal {}`
    *   Types use intersections `&`: `type Dog = Animal & { bark: () => void }`
2.  **Implementation**:
    *   Classes can implement both: `class UserImpl implements User {}` (as long as the `type` resolves to a static object shape).
3.  **Performance**:
    *   The TypeScript compiler caches relationships between interfaces better, so massive types might compile slightly slower than massive interfaces, though this rarely matters outside of gigantic codebases.

## Interview Questions

### When should you use `interface` vs `type`?
*   Use `interface` for defining object shapes, API responses, and class structures, especially if you are writing a library where users might need to augment your definitions (Declaration Merging).
*   Use `type` for primitives, unions, intersections, tuples, or complex mapped types (e.g., `ReturnType<T>`).

### Can an interface extend a type?
Yes, an interface can extend a type alias, *provided the type alias describes an object*. It cannot extend a union type.

## Common Gotchas

*   **Declaration Merging accidents**: Because interfaces auto-merge if they share the same name in the same scope, you might accidentally merge definitions without realizing it.

## Remember

> Interfaces are **open** (can be merged/extended later). Types are **closed** (fixed definitions, but can represent unions).
