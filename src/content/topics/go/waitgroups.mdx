## TL;DR

`sync.WaitGroup` is a concurrency primitive used to wait for a collection of goroutines to finish. It is essentially a thread-safe counter. You add to it before starting a goroutine, decrement it when a goroutine finishes, and block until the counter hits zero.

## Mental Model

```mermaid
flowchart TD
    Main["Main Goroutine"]
    WG["sync.WaitGroup Counter"]
    
    GR1(("Worker 1"))
    GR2(("Worker 2"))
    GR3(("Worker 3"))
    
    Main -->|wg.Add(3)| WG
    
    WG --- GR1
    WG --- GR2
    WG --- GR3
    
    GR1 -. "wg.Done() -> Counter = 2" .-> WG
    GR2 -. "wg.Done() -> Counter = 1" .-> WG
    GR3 -. "wg.Done() -> Counter = 0" .-> WG
    
    WG -->|Counter hits 0| MainResume["wg.Wait() unblocks"]
```

## Example

```go
package main

import (
	"fmt"
	"sync"
	"time"
)

func worker(id int, wg *sync.WaitGroup) {
	defer wg.Done() // 3. Decrement counter when finished
	
	fmt.Printf("Worker %d starting\n", id)
	time.Sleep(time.Second)
	fmt.Printf("Worker %d done\n", id)
}

func main() {
	var wg sync.WaitGroup

	for i := 1; i <= 3; i++ {
		wg.Add(1) // 1. Increment counter BEFORE launching
		go worker(i, &wg)
	}

	wg.Wait() // 2. Block until counter is 0
	fmt.Println("All workers finished.")
}
```

## How It Works

- **`wg.Add(int)`**: Increases the counter by the specified number.
- **`wg.Done()`**: Decreases the counter by 1. (It is literally just `wg.Add(-1)` under the hood).
- **`wg.Wait()`**: Blocks the execution of the calling goroutine until the counter becomes 0.

## Interview Questions

### What happens if you copy a WaitGroup by value?
WaitGroups, like Mutexes, contain an internal state that must not be copied. If you pass a `sync.WaitGroup` to a function by value, the function receives a copy of the counter. Calling `wg.Done()` on the copy will not affect the original, causing the `wg.Wait()` in main to block forever (deadlock). **Always pass WaitGroups by pointer (`*sync.WaitGroup`)**.

### Why must `wg.Add(1)` be called outside the goroutine?
If you call `wg.Add(1)` *inside* the goroutine:
```go
go func() {
    wg.Add(1) // BAD!
    defer wg.Done()
}()
wg.Wait()
```
The `main` goroutine might reach `wg.Wait()` before the background goroutine gets scheduled by the OS to run `wg.Add(1)`. Since the counter is initially 0, `wg.Wait()` will instantly unblock and exit the program before the worker even starts!

## Common Gotchas

*   **Negative Counters**: If you call `wg.Done()` too many times and the counter drops below zero, Go will **panic**.

## Remember

> If you launch a goroutine and immediately want to wait for it, use a `WaitGroup`. If you need to collect data back from it, use a `channel`.
