## TL;DR

The `context` package is used to carry deadlines, cancellation signals, and request-scoped values across API boundaries and between goroutines. It is standard practice to pass `ctx context.Context` as the very first argument to any function that does I/O.

## Example: Timeout Cancellation

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func slowOperation(ctx context.Context) {
	select {
	case <-time.After(3 * time.Second):
		fmt.Println("Operation finished successfully")
	case <-ctx.Done(): // Triggered if the context is cancelled
		fmt.Println("Operation aborted:", ctx.Err())
	}
}

func main() {
	// Create a context that automatically cancels after 1 second
	ctx, cancel := context.WithTimeout(context.Background(), 1*time.Second)
	defer cancel() // Always call cancel to free resources!

	// Pass it to the function
	slowOperation(ctx)
}
// Output: Operation aborted: context deadline exceeded
```

## Types of Contexts

1. **`context.Background()`**: The root context. Never cancelled, has no values. Use at the very top level (main, init, tests).
2. **`context.TODO()`**: Use when you are unsure what context to use or the surrounding function hasn't been updated to accept one yet.
3. **`context.WithCancel(parent)`**: Returns a copy of the parent with a `cancel()` function you can call manually.
4. **`context.WithTimeout(parent, duration)`**: Cancels automatically after a duration.
5. **`context.WithValue(parent, key, val)`**: Stores request-scoped data (like request IDs or user auth tokens).

## Interview Questions

### Why must you always call the `cancel()` function returned by `WithCancel` or `WithTimeout`?
If you don't call `cancel()`, the timer and internal structures created by the context remain in memory until they naturally expire or the parent is cancelled, creating a **Memory Leak**. Always use `defer cancel()`.

### How do contexts cascade?
If you derive a child context from a parent (`childCtx := context.WithCancel(parentCtx)`), cancelling the parent automatically cancels the child (and all its children). Cancelling the child does *not* cancel the parent.

## Common Gotchas

*   **Using context for optional parameters**: Do not use `context.WithValue` to pass optional function arguments or critical business logic. It is strictly for request-scoped data that transcends API boundaries (tracing, auth, logging). It acts like a hidden, untyped map, which breaks Go's static typing.

## Remember

> A Goroutine that you start should never be left to run forever if no one cares about the result anymore. `context` is how you tell them to stop.
