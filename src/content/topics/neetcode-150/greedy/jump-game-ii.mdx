## Problem Statement

You are given a **0-indexed** array of integers `nums` of length `n`. You are initially positioned at `nums[0]`.

Each element `nums[i]` represents the maximum length of a forward jump from index `i`. In other words, if you are at `nums[i]`, you can jump to any `nums[i + j]` where:
- `0 <= j <= nums[i]` and
- `i + j < n`

Return the **minimum number of jumps** to reach `nums[n - 1]`. The test cases are generated such that you can reach `nums[n - 1]`.

**Example 1:**
```text
Input: nums = [2,3,1,1,4]
Output: 2
Explanation: The minimum number of jumps to reach the last index is 2. 
             Jump 1 step from index 0 to 1, then 3 steps to the last index.
```

**Example 2:**
```text
Input: nums = [2,3,0,1,4]
Output: 2
```

**Constraints:**
- `1 <= nums.length <= 10^4`
- `0 <= nums[i] <= 1000`
- It's guaranteed that you can reach `nums[n - 1]`.


## The Intuition: Implicit BFS as a Greedy Sliding Window

### Why BFS?
Because we want the **minimum number of jumps**, this is equivalent to finding the shortest path in an unweighted directed graph, which is the canonical use case for **Breadth-First Search (BFS)**:
- **Level 0 (0 jumps):** Index `[0]`
- **Level 1 (1 jump):** All indices reachable from index `0`: `[1, nums[0]]`
- **Level 2 (2 jumps):** All indices reachable from any index in Level 1 that haven't been visited yet
- The first BFS level that includes the last index `n - 1` gives the minimum number of jumps!

### The Greedy Optimization ($O(1)$ Space)
In a traditional BFS, you would push indices into a `queue`, requiring $O(N)$ extra memory. 

However, notice a crucial geometric property of this problem:
> Every BFS level corresponds to a **contiguous interval of indices** `[left, right]`.

Instead of allocating a queue:
1. Maintain two pointers `left` and `right` defining the current BFS level window (initially `left = 0, right = 0`).
2. Iterate `i` through the current window `[left, right]`, finding the `farthest` index we can reach:  
   $$\text{farthest} = \max(\text{farthest}, i + \text{nums}[i])$$
3. Once we finish scanning the current window, we **must take 1 jump** to proceed to the next layer:
   - Increment `jumps++`.
   - Advance the window: `left = right + 1`, and `right = farthest`.
4. Repeat until `right >= n - 1`.

## Solution 1: Explicit BFS Window ($O(N)$ Time, $O(1)$ Space) - Recommended

This approach explicitly models the `[left, right]` BFS level intervals:

```javascript
/**
 * @param {number[]} nums
 * @return {number}
 */
var jump = function(nums) {
    let jumps = 0;
    let left = 0;
    let right = 0;
    const target = nums.length - 1;
    
    // While the current window has not yet reached or crossed the target
    while (right < target) {
        let farthest = 0;
        
        // Scan the entire current BFS level to find the furthest reachable index
        for (let i = left; i <= right; i++) {
            farthest = Math.max(farthest, i + nums[i]);
        }
        
        // Advance to the next BFS level
        left = right + 1;
        right = farthest;
        jumps++;
    }
    
    return jumps;
};
```


## Solution 2: Single-Pass Horizon Tracking ($O(N)$ Time, $O(1)$ Space)

We can simplify the loop into a single pass by tracking `currentEnd` (the boundary of the current jump):

```javascript
/**
 * @param {number[]} nums
 * @return {number}
 */
var jumpSinglePass = function(nums) {
    let jumps = 0;
    let currentEnd = 0;
    let farthest = 0;
    
    // We only need to iterate up to nums.length - 2
    // because once we reach the last index, we don't need to jump from it!
    for (let i = 0; i < nums.length - 1; i++) {
        farthest = Math.max(farthest, i + nums[i]);
        
        // Reached the end of the current jump's reach
        if (i === currentEnd) {
            jumps++;
            currentEnd = farthest;
            
            // Early exit if the target is already reachable
            if (currentEnd >= nums.length - 1) {
                break;
            }
        }
    }
    
    return jumps;
};
```


## Complexity Analysis

| Metric | Complexity | Notes |
| :--- | :--- | :--- |
| **Time Complexity** | $O(N)$ | Each index `i` is processed at most once as `left` and `right` continuously move forward from `0` to `N - 1`. |
| **Space Complexity** | $O(1)$ | No queue or dynamic memory is allocated; only pointers (`left`, `right`, `farthest`) are maintained. |
| **DP Alternative** | $O(N^2)$ | A bottom-up DP table `dp[i]` tracking min jumps takes $O(N^2)$ time and $O(N)$ space. |


## Edge Cases

- **Single Element (`nums = [0]` or `nums = [7]`):** `nums.length === 1`. `right < target` is initially false (`0 < 0`), returns `0` jumps immediately.
- **Two Elements (`nums = [1, 2]`):** `target = 1`. One jump reaches the end, returns `1`.
- **Large First Jump (`nums = [10, 1, 1, 1]`):** Index `0` reaches index `10 >= target`. In one jump, `right` becomes `10`, loop terminates with `jumps = 1`.
- **All 1s (`nums = [1, 1, 1, 1]`):** Must take individual steps of length 1; returns `nums.length - 1`.
