## Problem Statement

Given an integer array `nums`, find the subarray with the largest sum, and return its sum.

A **subarray** is a contiguous non-empty sequence of elements within an array.

**Example 1:**
```text
Input: nums = [-2,1,-3,4,-1,2,1,-5,4]
Output: 6
Explanation: The subarray [4,-1,2,1] has the largest sum 6.
```

**Example 2:**
```text
Input: nums = [1]
Output: 1
Explanation: The subarray [1] has the largest sum 1.
```

**Example 3:**
```text
Input: nums = [5,4,-1,7,8]
Output: 23
Explanation: The subarray [5,4,-1,7,8] has the largest sum 23.
```

**Constraints:**
- `1 <= nums.length <= 10^5`
- `-10^4 <= nums[i] <= 10^4`

**Follow up:** If you have figured out the $O(N)$ solution, try coding another solution using the **divide and conquer** approach, which is more subtle.


## The Greedy Insight: Kadane's Algorithm

### The Naive Trap ($O(N^2)$)
A brute-force solution checks all possible subarrays starting at index `i` and ending at index `j`, summing up values. With $N = 10^5$, an $O(N^2)$ algorithm performs $10^{10}$ operations, resulting in **Time Limit Exceeded (TLE)**.

### The Greedy Choice Property
As we iterate left to right, we accumulate values into a running total `currentSum`.

Suppose our accumulated `currentSum` becomes **negative** (`currentSum < 0`):
- Any subsequent number $x$ added to this negative prefix will be **smaller** than $x$ by itself:
  $$currentSum + x < x \quad (\text{since } currentSum < 0)$$
- A negative prefix contributes **negative value** to any future subarray!
- Therefore, carrying a negative running sum forward can **never** help us achieve a larger maximum sum.

> **Greedy Decision:** The moment `currentSum` drops below `0`, immediately **discard** the entire accumulated prefix and reset `currentSum = 0`. Start building a fresh candidate subarray from the next element!

## Optimal Solution: Kadane's Algorithm ($O(N)$ Time, $O(1)$ Space)

```javascript
/**
 * @param {number[]} nums
 * @return {number}
 */
var maxSubArray = function(nums) {
    let maxSum = nums[0];
    let currentSum = 0;
    
    for (const num of nums) {
        currentSum += num;
        
        // Update the maximum subarray sum found so far
        if (currentSum > maxSum) {
            maxSum = currentSum;
        }
        
        // Greedy reset: discard negative prefix
        if (currentSum < 0) {
            currentSum = 0;
        }
    }
    
    return maxSum;
};
```

> **Why check `maxSum` before resetting to `0`?**  
> If all numbers in `nums` are negative (e.g. `[-5, -2, -8]`), the correct answer is the largest single negative number (`-2`). By updating `maxSum` before resetting `currentSum = 0`, we correctly track the maximum element even when every prefix is negative.


## Follow-Up: Divide and Conquer ($O(N \log N)$ Time)

The follow-up asks for a Divide and Conquer solution.

Any maximum subarray within a range `[left, right]` must fall into one of three cases:
1. It lies entirely within the **left half**: `[left, mid]`.
2. It lies entirely within the **right half**: `[mid + 1, right]`.
3. It **crosses the midpoint** `mid` (spanning both left and right sides).

```javascript
/**
 * @param {number[]} nums
 * @return {number}
 */
var maxSubArrayDivideAndConquer = function(nums) {
    const findMaxCrossingSubarray = (left, mid, right) => {
        // Expand left from mid
        let leftSum = -Infinity;
        let sum = 0;
        for (let i = mid; i >= left; i--) {
            sum += nums[i];
            leftSum = Math.max(leftSum, sum);
        }
        
        // Expand right from mid + 1
        let rightSum = -Infinity;
        sum = 0;
        for (let i = mid + 1; i <= right; i++) {
            sum += nums[i];
            rightSum = Math.max(rightSum, sum);
        }
        
        return leftSum + rightSum;
    };
    
    const helper = (left, right) => {
        if (left === right) return nums[left];
        
        const mid = Math.floor((left + right) / 2);
        
        const leftMax = helper(left, mid);
        const rightMax = helper(mid + 1, right);
        const crossMax = findMaxCrossingSubarray(left, mid, right);
        
        return Math.max(leftMax, rightMax, crossMax);
    };
    
    return helper(0, nums.length - 1);
};
```


## Complexity Analysis

| Approach | Time Complexity | Space Complexity | Notes |
| :--- | :--- | :--- | :--- |
| **Kadane's (Greedy)** | $O(N)$ | $O(1)$ | Optimal. Single pass over the array with constant memory. |
| **Divide & Conquer** | $O(N \log N)$ | $O(\log N)$ | Recurrence $T(N) = 2T(N/2) + O(N)$. Call stack takes $O(\log N)$. |
| **Brute Force** | $O(N^2)$ | $O(1)$ | Evaluates all subarray pairs. Fails with TLE on $N = 10^5$. |


## Edge Cases

- **All Negative Numbers:** `[-3, -2, -5, -1]` $\to$ Returns `-1`. (The largest negative element).
- **Single Element:** `[5]` $\to$ Returns `5`. `[-3]` $\to$ Returns `-3`.
- **All Positive Numbers:** `[1, 2, 3, 4]` $\to$ Sums the entire array (`10`).
- **Alternating Signs with Large Peaks:** Correctly bridges negative dips if the subsequent positive surge outweighs the loss.
