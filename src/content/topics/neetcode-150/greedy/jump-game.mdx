## Problem Statement

You are given an integer array `nums`. You are initially positioned at the array's **first index**, and each element in the array represents your maximum jump length at that position.

Return `true` if you can reach the last index, or `false` otherwise.

**Example 1:**
```text
Input: nums = [2,3,1,1,4]
Output: true
Explanation: Jump 1 step from index 0 to 1, then 3 steps to the last index.
```

**Example 2:**
```text
Input: nums = [3,2,1,0,4]
Output: false
Explanation: You will always arrive at index 3 no matter what. 
             Its maximum jump length is 0, which makes it impossible to reach the last index.
```

**Constraints:**
- `1 <= nums.length <= 10^4`
- `0 <= nums[i] <= 10^5`


## The Intuition: From $O(N^2)$ DP to $O(N)$ Greedy

### Why Dynamic Programming is Overkill
A standard recursive backtracking or DP approach checks every possible jump from index `i`:
- At each index `i`, branch for every step size from `1` to `nums[i]`.
- With memoization, each state is computed once, but checking transitions takes $O(nums[i])$ per index, resulting in $O(N^2)$ worst-case time complexity.

### The Greedy Observation
We do not need to find the **shortest path** or list all paths; we only need to answer: **is the destination reachable?**

This problem can be solved with two distinct greedy perspectives:

1. **Backwards Greedy (Shifting the Goalpost):**
   - Place a `goal` at the final index: `goal = n - 1`.
   - Iterate backwards from right to left.
   - If an index `i` can jump far enough to reach the `goal` (`i + nums[i] >= goal`), then any jump that reaches `i` is also guaranteed to reach the final index!
   - We greedily shift our `goal` to `i`: `goal = i`.
   - If `goal` reaches `0` by the end of the scan, a valid path exists!

2. **Forwards Greedy (Max Reach Horizon):**
   - Keep track of the furthest index reachable so far: `maxReach = 0`.
   - Iterate forwards through the array.
   - If the current index `i` is greater than `maxReach`, we have hit an unreachable gap and return `false`.
   - Otherwise, expand the horizon: `maxReach = Math.max(maxReach, i + nums[i])`.
   - If `maxReach >= n - 1`, we can reach the end immediately.

## Solution 1: Backwards Greedy (Goalpost Shift) - Recommended

```javascript
/**
 * @param {number[]} nums
 * @return {boolean}
 */
var canJump = function(nums) {
    let goal = nums.length - 1;
    
    // Scan backwards from the second-to-last element down to index 0
    for (let i = nums.length - 2; i >= 0; i--) {
        // Can we jump from index i to or past the current goal?
        if (i + nums[i] >= goal) {
            goal = i; // Move the goalpost closer
        }
    }
    
    // If the goal shifted all the way back to the start, a path exists
    return goal === 0;
};
```


## Solution 2: Forwards Greedy (Max Reach Horizon)

```javascript
/**
 * @param {number[]} nums
 * @return {boolean}
 */
var canJumpForward = function(nums) {
    let maxReach = 0;
    const target = nums.length - 1;
    
    for (let i = 0; i < nums.length; i++) {
        // If current index is beyond our furthest reach, we are stuck
        if (i > maxReach) {
            return false;
        }
        
        // Expand the horizon with the maximum jump from here
        maxReach = Math.max(maxReach, i + nums[i]);
        
        // Early exit: destination is already within reach
        if (maxReach >= target) {
            return true;
        }
    }
    
    return true;
};
```


## Complexity Analysis

| Approach | Time Complexity | Space Complexity | Notes |
| :--- | :--- | :--- | :--- |
| **Backwards Greedy** | $O(N)$ | $O(1)$ | Single reverse pass. Shifts goalpost in-place with zero memory allocation. |
| **Forwards Greedy** | $O(N)$ | $O(1)$ | Single forward pass with early termination when `maxReach >= target`. |
| **Dynamic Programming** | $O(N^2)$ | $O(N)$ | Checks all jump sizes at each index. Redundant and slow for large $N$. |


## Edge Cases

- **Single Element (`nums = [0]`):** Returns `true` immediately because start index `0` is already the last index.
- **Immediate Trap (`nums = [0, 2, 3]`):** Returns `false` because we cannot jump past index `0`.
- **Large Initial Jump (`nums = [10, 0, 0, 0]`):** Returns `true` as the first jump comfortably clears all zeros.
- **Zero in the Middle with Overshoot (`nums = [2, 0, 0]`):** Returns `true` because index `0` jumps 2 steps directly to the end.
