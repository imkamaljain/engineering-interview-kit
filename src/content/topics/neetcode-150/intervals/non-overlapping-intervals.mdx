## Problem Statement

Given an array of intervals `intervals` where `intervals[i] = [start_i, end_i]`, return the **minimum number of intervals** you need to remove to make the rest of the intervals non-overlapping.

> **Note:** Intervals that touch at a single point (e.g., `[1, 2]` and `[2, 3]`) are **non-overlapping**.

**Example 1:**
```text
Input: intervals = [[1,2],[2,3],[3,4],[1,3]]
Output: 1
Explanation: [1,3] can be removed and the rest of the intervals are non-overlapping.
```

**Example 2:**
```text
Input: intervals = [[1,2],[1,2],[1,2]]
Output: 2
Explanation: You need to remove two [1,2] to make the rest of the intervals non-overlapping.
```

**Example 3:**
```text
Input: intervals = [[1,2],[2,3]]
Output: 0
Explanation: You don't need to remove any of the intervals since they're already non-overlapping.
```

**Constraints:**
- `1 <= intervals.length <= 10^5`
- `intervals[i].length == 2`
- `-5 * 10^4 <= start_i < end_i <= 5 * 10^4`


## Approach: The Greedy Choice

This is the classic **Interval Scheduling Maximization Problem**:
> Minimizing the number of intervals to remove is mathematically identical to **maximizing the number of mutually compatible, non-overlapping intervals** we can keep.

### Which Interval Should We Remove During a Conflict?
Suppose two intervals overlap:
- Interval $A$: `[1, 100]`
- Interval $B$: `[2, 3]`

We can only keep **one** of them. Which one should we keep?
- If we keep $A$ (`[1, 100]`), it hogs the timeline all the way until time 100, blocking dozens of potential future intervals.
- If we keep $B$ (`[2, 3]`), it finishes early at time 3, leaving the vast majority of the timeline open for future non-overlapping intervals.

**The Greedy Rule:**
> Whenever two intervals conflict, **always remove the interval that ends later** (keep the one with the smaller `end` time).

## Solution

### Approach 1: Sort by Start Time (Standard Pattern)

Sorting by `start` time keeps our logic consistent with other interval problems (e.g. Merge Intervals, Insert Interval):

```javascript
/**
 * @param {number[][]} intervals
 * @return {number}
 */
var eraseOverlapIntervals = function(intervals) {
    if (intervals.length <= 1) return 0;

    // 1. Sort by start time ascending
    intervals.sort((a, b) => a[0] - b[0]);

    let removals = 0;
    let prevEnd = intervals[0][1];

    for (let i = 1; i < intervals.length; i++) {
        const [currStart, currEnd] = intervals[i];

        // Conflict: current interval starts before previous interval finishes
        if (currStart < prevEnd) {
            removals++;
            // Greedily keep the interval with the smaller end time
            prevEnd = Math.min(prevEnd, currEnd);
        } else {
            // No conflict: update end pointer to current interval's end
            prevEnd = currEnd;
        }
    }

    return removals;
};
```

### Approach 2: Sort by End Time (Classic Activity Selection)

Sorting directly by `end` time simplifies the conflict logic:

```javascript
/**
 * @param {number[][]} intervals
 * @return {number}
 */
var eraseOverlapIntervalsByEnd = function(intervals) {
    if (intervals.length <= 1) return 0;

    // 1. Sort by end time ascending
    intervals.sort((a, b) => a[1] - b[1]);

    let removals = 0;
    let prevEnd = intervals[0][1];

    for (let i = 1; i < intervals.length; i++) {
        const [currStart, currEnd] = intervals[i];

        // Overlap detected: must drop the current interval
        if (currStart < prevEnd) {
            removals++;
        } else {
            // No overlap: update boundary
            prevEnd = currEnd;
        }
    }

    return removals;
};
```


## Complexity Analysis

- **Time Complexity:** $O(N \log N)$
  - Sorting $N$ intervals takes $O(N \log N)$ time.
  - The subsequent single-pass linear scan takes $O(N)$ time.
  - Total time: $O(N \log N)$.
- **Space Complexity:** $O(1)$ (or $O(\log N)$)
  - Sorting in-place uses $O(1)$ auxiliary storage (or $O(\log N)$ stack space for the sorting algorithm).
