## Problem Statement

You are given an array of non-overlapping intervals `intervals` where `intervals[i] = [start_i, end_i]` represents the start and the end of the $i^{\text{th}}$ interval and `intervals` is sorted in ascending order by `start_i`. You are also given an interval `newInterval = [start, end]` that represents the start and end of another interval.

Insert `newInterval` into `intervals` such that `intervals` is still sorted in ascending order by `start_i` and `intervals` still does not have any overlapping intervals (merge overlapping intervals if necessary).

Return `intervals` after the insertion.

You do not need to modify `intervals` in-place. You can make a new array and return it.

**Example 1:**
```text
Input: intervals = [[1,3],[6,9]], newInterval = [2,5]
Output: [[1,5],[6,9]]
Explanation: [2,5] overlaps with [1,3], merging them into [1,5].
```

**Example 2:**
```text
Input: intervals = [[1,2],[3,5],[6,7],[8,10],[12,16]], newInterval = [4,8]
Output: [[1,2],[3,10],[12,16]]
Explanation: Because the new interval [4,8] overlaps with [3,5],[6,7],[8,10].
```

**Constraints:**
- `0 <= intervals.length <= 10^4`
- `intervals[i].length == 2`
- `0 <= start_i <= end_i <= 10^5`
- `intervals` is sorted by `start_i` in ascending order.
- `newInterval.length == 2`
- `0 <= start <= end <= 10^5`


## The 3-Phase Linear Scan ($O(N)$)

Unlike general interval problems (like **LeetCode #56 Merge Intervals**) that require an initial $O(N \log N)$ sorting step, `intervals` is **already sorted** and guaranteed to have no initial overlaps!

Because of this pre-sorted order, inserting `newInterval` divides our iteration into **three sequential, chronological phases**:

1. **Phase 1: Strictly Before `newInterval`**
   - Condition: `intervals[i][1] < newInterval[0]`
   - The current interval finishes before `newInterval` even begins.
   - Action: Push `intervals[i]` directly to `result`.

2. **Phase 2: Overlapping Intervals**
   - Condition: `intervals[i][0] <= newInterval[1]`
   - There is an active overlap between `intervals[i]` and `newInterval`.
   - Action: Merge `intervals[i]` into `newInterval` by expanding boundaries:
     $$\text{newInterval}[0] = \min(\text{newInterval}[0], \text{intervals}[i][0])$$
     $$\text{newInterval}[1] = \max(\text{newInterval}[1], \text{intervals}[i][1])$$
   - Continue until the overlap ceases, then push the merged `newInterval` to `result`.

3. **Phase 3: Strictly After `newInterval`**
   - Condition: All remaining intervals where `intervals[i][0] > newInterval[1]`
   - Action: Push all remaining intervals directly to `result`.

## Solution

```javascript
/**
 * @param {number[][]} intervals
 * @param {number[]} newInterval
 * @return {number[][]}
 */
var insert = function(intervals, newInterval) {
    const result = [];
    let i = 0;
    const n = intervals.length;

    // Phase 1: Add all intervals that finish strictly BEFORE newInterval begins
    while (i < n && intervals[i][1] < newInterval[0]) {
        result.push(intervals[i]);
        i++;
    }

    // Phase 2: Absorb and merge all overlapping intervals into newInterval
    while (i < n && intervals[i][0] <= newInterval[1]) {
        newInterval[0] = Math.min(newInterval[0], intervals[i][0]);
        newInterval[1] = Math.max(newInterval[1], intervals[i][1]);
        i++;
    }
    // Append the fully merged newInterval
    result.push(newInterval);

    // Phase 3: Add all remaining intervals that begin strictly AFTER newInterval ends
    while (i < n) {
        result.push(intervals[i]);
        i++;
    }

    return result;
};
```


## Complexity Analysis

- **Time Complexity:** $O(N)$
  - Because `intervals` is pre-sorted, we traverse each interval at most once across the three sequential while loops.
  - No sorting is required, giving a clean $O(N)$ single-pass solution.
- **Space Complexity:** $O(N)$
  - To store the output array `result`, which holds at most $N + 1$ intervals.
  - $O(1)$ auxiliary space beyond the output array.
