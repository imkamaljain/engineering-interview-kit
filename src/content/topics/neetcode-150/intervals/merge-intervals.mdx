## Problem Statement

Given an array of `intervals` where `intervals[i] = [start_i, end_i]`, merge all overlapping intervals, and return *an array of the non-overlapping intervals that cover all the intervals in the input*.

**Example 1:**
```text
Input: intervals = [[1,3],[2,6],[8,10],[15,18]]
Output: [[1,6],[8,10],[15,18]]
Explanation: Since intervals [1,3] and [2,6] overlap, merge them into [1,6].
```

**Example 2:**
```text
Input: intervals = [[1,4],[4,5]]
Output: [[1,5]]
Explanation: Intervals [1,4] and [4,5] are considered overlapping.
```

**Constraints:**
- `1 <= intervals.length <= 10^4`
- `intervals[i].length == 2`
- `0 <= start_i <= end_i <= 10^4`


## Approach: Sort & Linear Merge

The fundamental challenge with unsorted intervals is that any interval could potentially overlap with any other interval anywhere in the array. Comparing all pairs would require $O(N^2)$ checks.

### The Golden Rule: Sort by Start Time
By sorting the intervals by their starting times (`intervals.sort((a, b) => a[0] - b[0])`), we guarantee a critical invariant:
> If interval $B$ starts after interval $A$, it can **only** overlap with $A$ if its start time is $\le$ $A$'s end time ($B.\text{start} \le A.\text{end}$).

Once sorted, we only need a single pass through the list:
1. Initialize `result` with the first interval: `result = [intervals[0]]`.
2. Iterate through the rest of the intervals:
   - Let `prev = result[result.length - 1]`.
   - **Case 1: Overlap (`curr[0] <= prev[1]`):**
     Extend the end boundary of `prev`:
     $$\text{prev}[1] = \max(\text{prev}[1], \text{curr}[1])$$
   - **Case 2: No Overlap (`curr[0] > prev[1]`):**
     Push `curr` into `result` as a new disjoint interval.
3. Return `result`.

### Why `Math.max` is Essential (Envelopment / Containment)
A common beginner bug is setting `prev[1] = curr[1]`.
Consider `intervals = [[1, 10], [2, 5]]`:
- `2 <= 10`, so they overlap.
- If we blindly set `prev[1] = 5`, the merged interval becomes `[1, 5]`, which is incorrect!
- The first interval `[1, 10]` completely swallows `[2, 5]`. Using `Math.max(10, 5) = 10` ensures complete containment is handled safely.

## Solution

```javascript
/**
 * @param {number[][]} intervals
 * @return {number[][]}
 */
var merge = function(intervals) {
    if (intervals.length <= 1) return intervals;

    // 1. Sort intervals by start time ascending
    intervals.sort((a, b) => a[0] - b[0]);

    const result = [intervals[0]];

    // 2. Linear scan through sorted intervals
    for (let i = 1; i < intervals.length; i++) {
        const [currStart, currEnd] = intervals[i];
        const prev = result[result.length - 1];

        // Check if current interval overlaps with previous merged interval
        if (currStart <= prev[1]) {
            // Overlap: stretch previous interval's end boundary
            prev[1] = Math.max(prev[1], currEnd);
        } else {
            // Disjoint interval: start a new entry in result
            result.push([currStart, currEnd]);
        }
    }

    return result;
};
```


## Complexity Analysis

- **Time Complexity:** $O(N \log N)$
  - Sorting the array of $N$ intervals takes $O(N \log N)$ time.
  - The subsequent linear scan processes each interval in $O(1)$ time, taking $O(N)$ total.
  - Dominant overall runtime: $O(N \log N)$.
- **Space Complexity:** $O(N)$
  - $O(N)$ space to store the output array `result` (or $O(\log N)$ / $O(N)$ auxiliary space used by JavaScript's Timsort implementation).
