## Problem Statement

You are given an integer array `coins` representing coins of different denominations and an integer `amount` representing a total amount of money.

Return the **fewest number of coins** that you need to make up that amount. If that amount of money cannot be made up by any combination of the coins, return `-1`.

You may assume that you have an **infinite number** of each kind of coin.

**Example 1:**
```text
Input: coins = [1,2,5], amount = 11
Output: 3
Explanation: 11 = 5 + 5 + 1
```

**Example 2:**
```text
Input: coins = [2], amount = 3
Output: -1
```

**Example 3:**
```text
Input: coins = [1], amount = 0
Output: 0
```

**Constraints:**
- `1 <= coins.length <= 12`
- `1 <= coins[i] <= 2^31 - 1`
- `0 <= amount <= 10^4`


## Why Greedy Fails: The Need for DP

In conventional currency systems (like US coins: 1, 5, 10, 25), greedily choosing the largest possible coin always yields the optimal solution.

However, for arbitrary denominations, **a greedy approach fails**:
- Suppose `coins = [1, 3, 4, 5]` and `amount = 7`.
- **Greedy Strategy:** Grabs `5`, leaving `2` $\to$ grabs two `1`s. Total = `5 + 1 + 1` (**3 coins**).
- **Optimal DP Strategy:** Grabs `4` and `3`. Total = `4 + 3` (**2 coins**).

Because locally optimal choices do not guarantee a globally optimal total, we must use **Dynamic Programming** (the Unbounded Knapsack pattern).


## The Dynamic Programming Recurrence

Let $\text{dp}[a]$ be the **minimum number of coins** required to form amount $a$:

1. **Base Case:**
   - $\text{dp}[0] = 0$ (zero coins are needed to make an amount of 0).
   - Initialize all other entries $\text{dp}[1 \dots \text{amount}]$ to $\infty$ (or $\text{amount} + 1$).

2. **Transition:**
   To make amount $a$, we could use any coin $c \in \text{coins}$ (as long as $c \le a$). If we use coin $c$, the remaining amount to form is $a - c$, which requires $\text{dp}[a - c]$ coins:

   $$\text{dp}[a] = \min_{c \in \text{coins},\; c \le a} (\text{dp}[a - c] + 1)$$

3. **Result:**
   - If $\text{dp}[\text{amount}] > \text{amount}$, the target amount was unreachable $\to$ return `-1`.
   - Otherwise, return $\text{dp}[\text{amount}]$.

## Optimal Solution: Bottom-Up Tabulation ($O(A \times C)$ Time, $O(A)$ Space)

```javascript
/**
 * @param {number[]} coins
 * @param {number} amount
 * @return {number}
 */
var coinChange = function(coins, amount) {
    if (amount === 0) return 0;
    
    // dp[a] stores minimum coins to make amount 'a'
    // Initialize with amount + 1 (acts as infinity since min coins <= amount)
    const dp = new Int32Array(amount + 1).fill(amount + 1);
    dp[0] = 0; // Base case: 0 coins for amount 0
    
    for (let a = 1; a <= amount; a++) {
        for (const coin of coins) {
            if (a - coin >= 0) {
                dp[a] = Math.min(dp[a], dp[a - coin] + 1);
            }
        }
    }
    
    // If dp[amount] was never updated from infinity, amount is unreachable
    return dp[amount] > amount ? -1 : dp[amount];
};
```

> **Why fill with `amount + 1` instead of `Infinity`?**  
> Since the smallest possible coin has value `1`, the maximum number of coins required for any amount $A$ is $A$ (using all $1$-cent coins). Any value greater than $A$ (like $A + 1$) represents an unreachable state while fitting cleanly in standard typed integers (`Int32Array`).


## Alternative: Top-Down Recursion with Memoization

```javascript
/**
 * @param {number[]} coins
 * @param {number} amount
 * @return {number}
 */
var coinChangeMemo = function(coins, amount) {
    const memo = new Map();
    
    const dfs = (rem) => {
        if (rem === 0) return 0;
        if (rem < 0) return -1;
        if (memo.has(rem)) return memo.get(rem);
        
        let minCoins = Infinity;
        
        for (const coin of coins) {
            const res = dfs(rem - coin);
            if (res >= 0 && res < minCoins) {
                minCoins = res + 1;
            }
        }
        
        const ans = minCoins === Infinity ? -1 : minCoins;
        memo.set(rem, ans);
        return ans;
    };
    
    return dfs(amount);
};
```


## Complexity Analysis

| Metric | Complexity | Notes |
| :--- | :--- | :--- |
| **Time Complexity** | $O(A \times C)$ | Where $A = \text{amount}$ and $C = \text{coins.length}$. For each amount from $1 \dots A$, we iterate through all $C$ coins. |
| **Space Complexity** | $O(A)$ | DP array of size $A + 1$ requires $O(A)$ memory. |
| **BFS Graph Alternative** | $O(A \times C)$ | Shortest path on unweighted DAG from $0$ to $A$ using a queue and visited set. |


## Edge Cases

- **Zero Amount (`amount = 0`):** Handled in $O(1)$; returns `0`.
- **Impossible Amount (`coins = [2], amount = 3`):** Odd amount cannot be reached with even coins; returns `-1`.
- **Single Coin Exact Match (`coins = [5], amount = 5`):** Returns `1`.
- **Coin Larger than Amount (`coins = [5], amount = 3`):** No coin can be chosen; returns `-1`.
