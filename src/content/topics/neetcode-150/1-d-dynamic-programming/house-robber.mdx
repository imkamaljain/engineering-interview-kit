## Problem Statement

You are a professional robber planning to rob houses along a street. Each house has a certain amount of money stashed, the only constraint stopping you from robbing each of them is that adjacent houses have security systems connected and **it will automatically contact the police if two adjacent houses were broken into on the same night**.

Given an integer array `nums` representing the amount of money of each house, return the **maximum amount of money you can rob tonight without alerting the police**.

**Example 1:**
```text
Input: nums = [1,2,3,1]
Output: 4
Explanation:
Rob house 1 (money = 1) and then rob house 3 (money = 3).
Total amount you can rob = 1 + 3 = 4.
```

**Example 2:**
```text
Input: nums = [2,7,9,3,1]
Output: 12
Explanation:
Rob house 1 (money = 2), rob house 3 (money = 9) and rob house 5 (money = 1).
Total amount you can rob = 2 + 9 + 1 = 12.
```

**Constraints:**
- `1 <= nums.length <= 100`
- `0 <= nums[i] <= 400`


## The Dynamic Programming Intuition

### The Decision at Each House
When standing outside house $i$, you have exactly two mutually exclusive choices:

1. **Rob House $i$:**
   - You take the money in this house: `nums[i]`.
   - Because adjacent houses cannot be robbed, you **must skip** house $i - 1$.
   - The maximum money you could have robbed from previous houses is whatever you could make up to house $i - 2$: `dp[i - 2]`.
   - Total: $\text{nums}[i] + \text{dp}[i - 2]$

2. **Skip House $i$:**
   - You take `0` from house $i$.
   - You are free to keep whatever optimal loot was robbed up to house $i - 1$: `dp[i - 1]`.
   - Total: $\text{dp}[i - 1]$

### The Recurrence Relation
Taking the best of both choices yields:

$$\text{dp}[i] = \max(\text{dp}[i - 1],\; \text{dp}[i - 2] + \text{nums}[i])$$

Notice the familiar structure: just like *Climbing Stairs*, computing the optimal decision at index $i$ **only depends on the results of the two immediate previous houses** ($i - 1$ and $i - 2$).

## Solution 1: Space-Optimized DP ($O(N)$ Time, $O(1)$ Space) - Recommended

Instead of maintaining a full array of size $N$, we track only two variables: `prev2` ($\text{dp}[i - 2]$) and `prev1` ($\text{dp}[i - 1]$):

```javascript
/**
 * @param {number[]} nums
 * @return {number}
 */
var rob = function(nums) {
    let prev2 = 0; // Represents max loot up to i - 2
    let prev1 = 0; // Represents max loot up to i - 1
    
    for (const num of nums) {
        // Decide: skip current house (prev1) OR rob it (prev2 + num)
        const curr = Math.max(prev1, prev2 + num);
        prev2 = prev1;
        prev1 = curr;
    }
    
    return prev1;
};
```

> **Why initialize `prev2 = 0` and `prev1 = 0`?**  
> On the first iteration, `Math.max(0, 0 + nums[0]) = nums[0]`. On the second iteration, `Math.max(nums[0], 0 + nums[1])`. This elegantly handles arrays of length 1 and 2 without requiring separate `if (nums.length <= 2)` edge-case branches!


## Solution 2: Bottom-Up Tabulation ($O(N)$ Time, $O(N)$ Space)

Explicit DP table storing max loot up to house $i$:

```javascript
/**
 * @param {number[]} nums
 * @return {number}
 */
var robTabulation = function(nums) {
    if (nums.length === 1) return nums[0];
    
    const dp = new Int32Array(nums.length);
    dp[0] = nums[0];
    dp[1] = Math.max(nums[0], nums[1]);
    
    for (let i = 2; i < nums.length; i++) {
        dp[i] = Math.max(dp[i - 1], dp[i - 2] + nums[i]);
    }
    
    return dp[nums.length - 1];
};
```


## Solution 3: Top-Down Recursion with Memoization ($O(N)$ Time, $O(N)$ Space)

Recursive choice with caching:

```javascript
/**
 * @param {number[]} nums
 * @return {number}
 */
var robMemo = function(nums) {
    const memo = new Map();
    
    const helper = (i) => {
        // Base case: past the beginning of the street
        if (i < 0) return 0;
        if (memo.has(i)) return memo.get(i);
        
        const loot = Math.max(
            helper(i - 1),            // Skip house i
            helper(i - 2) + nums[i]   // Rob house i
        );
        
        memo.set(i, loot);
        return loot;
    };
    
    return helper(nums.length - 1);
};
```


## Complexity Analysis

| Approach | Time Complexity | Space Complexity | Notes |
| :--- | :--- | :--- | :--- |
| **Space-Optimized (Rolling)** | $O(N)$ | $O(1)$ | Optimal. Only tracks `prev1` and `prev2` in registers. |
| **Bottom-Up Tabulation** | $O(N)$ | $O(N)$ | Tabulates intermediate optimal loot across all $N$ houses. |
| **Top-Down Memoization** | $O(N)$ | $O(N)$ | Call stack and cache each reach $O(N)$ depth. |
| **Brute Force (Recursion)** | $O(2^N)$ | $O(N)$ | Evaluates every valid subset of non-adjacent houses; TLE. |


## Edge Cases

- **Single House (`nums = [7]`):** Loop executes once; `prev1` becomes `7`.
- **Two Houses (`nums = [10, 2]`):** Robs the richer house; returns `10`.
- **All Same Values (`nums = [4, 4, 4, 4]`):** Can only rob alternate houses; returns `4 + 4 = 8`.
- **Zeros in Array (`nums = [2, 0, 0, 2]`):** Correctly handles zero-value houses without issues; returns `4`.
