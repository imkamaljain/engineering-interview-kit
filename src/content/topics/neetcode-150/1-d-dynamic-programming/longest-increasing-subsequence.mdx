## Problem Statement

Given an integer array `nums`, return the length of the **longest strictly increasing subsequence**.

A **subsequence** is derived from an array by deleting some or no elements without changing the order of the remaining elements (unlike a subarray, a subsequence does not need to be contiguous).

**Example 1:**
```text
Input: nums = [10,9,2,5,3,7,101,18]
Output: 4
Explanation: The longest increasing subsequence is [2,3,7,101], therefore the length is 4.
([2,3,7,18] is also a valid increasing subsequence of length 4).
```

**Example 2:**
```text
Input: nums = [0,1,0,3,2,3]
Output: 4
Explanation: The longest increasing subsequence is [0,1,2,3], with length 4.
```

**Example 3:**
```text
Input: nums = [7,7,7,7,7,7,7]
Output: 1
Explanation: A strictly increasing subsequence must have strictly greater elements.
```

**Constraints:**
- `1 <= nums.length <= 2500`
- `-10^4 <= nums[i] <= 10^4`

**Follow up:** Can you come up with an algorithm that runs in $O(N \log N)$ time complexity?


## Approach 1: Classic Dynamic Programming ($O(N^2)$ Time, $O(N)$ Space)

### State Definition
Let $\text{dp}[i]$ represent the **length of the longest strictly increasing subsequence that ends at index $i$**.

### Base Case
Every single element by itself forms a valid increasing subsequence of length 1:
$$\text{dp}[i] = 1 \quad \text{for all } 0 \le i < n$$

### Recurrence Relation
For each element at index $i$, we look back at every previous element at index $j$ ($0 \le j < i$):
- If $\text{nums}[j] < \text{nums}[i]$, we can extend any subsequence ending at $j$ by appending $\text{nums}[i]$.
- The new length would be $\text{dp}[j] + 1$.

$$\text{dp}[i] = \max_{0 \le j < i,\; \text{nums}[j] < \text{nums}[i]} (\text{dp}[j] + 1)$$

The final answer is the maximum value across the entire $\text{dp}$ array: $\max(\text{dp})$.


## Approach 2: Patience Sorting & Binary Search ($O(N \log N)$ Time, $O(N)$ Space) - Optimal

To improve from $O(N^2)$ to $O(N \log N)$, we use **Patience Sorting** (similar to playing solitaire):

1. Maintain an array `tails`, where `tails[k]` stores the **smallest tail element** of all increasing subsequences of length $k + 1$ found so far.
2. For each number $x$ in `nums`:
   - Use **binary search** to find the first index in `tails` with an element $\ge x$.
   - **Case 1 (Extend):** If $x$ is larger than all elements in `tails`, append $x$ to the end of `tails`. This increases the length of the longest subsequence by 1!
   - **Case 2 (Greedy Replacement):** If `tails[idx] >= x`, overwrite `tails[idx] = x`.
     - *Why replace?* Having a smaller ending value for a subsequence of that length makes it **strictly easier** for future numbers to be greater than it and extend the sequence!
3. The length of `tails` at the end is the length of the longest increasing subsequence.

## Solution 1: Classic DP ($O(N^2)$ Time, $O(N)$ Space)

```javascript
/**
 * @param {number[]} nums
 * @return {number}
 */
var lengthOfLIS_DP = function(nums) {
    const n = nums.length;
    // Every element is an increasing subsequence of length 1
    const dp = new Int32Array(n).fill(1);
    let maxLIS = 1;
    
    for (let i = 1; i < n; i++) {
        for (let j = 0; j < i; j++) {
            if (nums[j] < nums[i]) {
                dp[i] = Math.max(dp[i], dp[j] + 1);
            }
        }
        maxLIS = Math.max(maxLIS, dp[i]);
    }
    
    return maxLIS;
};
```


## Solution 2: Patience Sorting with Binary Search ($O(N \log N)$ Time, $O(N)$ Space) - Recommended

```javascript
/**
 * @param {number[]} nums
 * @return {number}
 */
var lengthOfLIS = function(nums) {
    const tails = [];
    
    for (const x of nums) {
        // Binary search for the first element in tails that is >= x
        let left = 0;
        let right = tails.length - 1;
        let insertIdx = tails.length;
        
        while (left <= right) {
            const mid = Math.floor((left + right) / 2);
            if (tails[mid] >= x) {
                insertIdx = mid;
                right = mid - 1; // Look for an earlier position
            } else {
                left = mid + 1;
            }
        }
        
        // If x is larger than all tails, extend the subsequence
        if (insertIdx === tails.length) {
            tails.push(x);
        } else {
            // Greedily update the tail for this length with a smaller value
            tails[insertIdx] = x;
        }
    }
    
    return tails.length;
};
```

> **Important Note:**  
> The `tails` array does **not** necessarily store the actual subsequence elements in order (e.g. `[2, 3, 7, 18]` vs `[2, 3, 7, 101]`), but its **length** is strictly guaranteed to equal the maximum length of an increasing subsequence.


## Complexity Analysis

| Approach | Time Complexity | Space Complexity | Notes |
| :--- | :--- | :--- | :--- |
| **Classic DP** | $O(N^2)$ | $O(N)$ | Nested loops over all pairs $(i, j)$. Clean and easy to reconstruct the actual sequence. |
| **Binary Search (Patience)** | $O(N \log N)$ | $O(N)$ | Optimal. $N$ elements each processed via $O(\log N)$ binary search. |


## Edge Cases

- **Single Element (`nums = [5]`):** Returns `1`.
- **Strictly Decreasing (`nums = [5, 4, 3, 2, 1]`):** Overwrites `tails[0]` on each step; final length is `1`.
- **All Identical Values (`nums = [7, 7, 7, 7]`):** Strictly increasing requirement means duplicates replace `tails[0]`; returns `1`.
- **Already Sorted (`nums = [1, 2, 3, 4]`):** Appends on every step; returns `4`.
