## Problem Statement

Given an array `nums` containing `n` distinct numbers in the range `[0, n]`, return *the only number in the range that is missing from the array*.

**Example 1:**
```text
Input: nums = [3,0,1]
Output: 2
Explanation: 
n = 3 since there are 3 numbers, so all numbers are in the range [0, 3]. 
2 is the missing number because it does not appear in nums.
```

**Example 2:**
```text
Input: nums = [0,1]
Output: 2
Explanation: 
n = 2 since there are 2 numbers, so all numbers are in the range [0, 2]. 
2 is the missing number because it does not appear in nums.
```

**Example 3:**
```text
Input: nums = [9,6,4,2,3,5,7,0,1]
Output: 8
Explanation: 
n = 9, so all numbers are in [0, 9]. 
8 is the missing number because it does not appear in nums.
```

**Constraints:**
- `n == nums.length`
- `1 <= n <= 10^4`
- `0 <= nums[i] <= n`
- All the numbers of `nums` are **unique**.

**Follow up:**
Could you implement a solution using only $O(1)$ extra space complexity and $O(N)$ runtime complexity?


## Approach 1: Bit Manipulation (XOR Cancellation)

We can treat this problem as an extension of **LeetCode #136 (Single Number)**:
- The input array contains $n$ numbers from the range `[0, n]`.
- If we consider the union of all numbers in `nums` and all expected integers `0, 1, 2, ..., n`:
  - Every present number appears **twice** (once in `nums`, once in the range `[0, n]`).
  - The missing number appears **only once** (in the range `[0, n]`, but never in `nums`).

Using the self-cancellation property of XOR (`x ^ x = 0` and `x ^ 0 = x`):
- All duplicate pairs cancel each other out to zero.
- Only the missing number survives!

### The Algorithm:
1. Initialize `result = nums.length` (seed with $n$ because array indices only range from $0$ to $n - 1$).
2. Loop through `i = 0` to `n - 1`:
   - XOR `result` with the index `i` AND with the array value `nums[i]`:
     ```text
     result ^= i ^ nums[i]
     ```
3. Return `result`.

> **Key Advantage:** Unlike arithmetic summation, bitwise XOR is completely **immune to integer overflow**!


## Approach 2: Gauss's Summation Formula

The sum of all consecutive integers from $0$ to $n$ is given by Gauss's arithmetic formula:
$$\text{Expected Sum} = \frac{n(n + 1)}{2}$$

By subtracting the sum of all elements in `nums` from this expected sum, the remaining difference must be the missing number:
$$\text{Missing} = \frac{n(n + 1)}{2} - \sum_{i=0}^{n-1} \text{nums}[i]$$

## Solution

### Optimal: XOR Bit Manipulation

```javascript
/**
 * @param {number[]} nums
 * @return {number}
 */
var missingNumber = function(nums) {
    const n = nums.length;
    let missing = n; // Seed with n, as loop indices only reach n - 1
    
    for (let i = 0; i < n; i++) {
        // XOR index and array value
        missing ^= i ^ nums[i];
    }
    
    return missing;
};
```

### Alternative: Gauss Sum Formula

```javascript
/**
 * @param {number[]} nums
 * @return {number}
 */
var missingNumberMath = function(nums) {
    const n = nums.length;
    const expectedSum = (n * (n + 1)) / 2;
    const actualSum = nums.reduce((sum, num) => sum + num, 0);
    
    return expectedSum - actualSum;
};
```


## Complexity Analysis

- **Bit Manipulation (XOR):**
  - **Time Complexity:** $O(N)$ — Single pass through the array of length $N$.
  - **Space Complexity:** $O(1)$ — Only a single accumulator variable `missing`.
  - **Overflow Safety:** 100% immune to integer overflow.
- **Gauss Math:**
  - **Time Complexity:** $O(N)$ — Single pass to sum elements.
  - **Space Complexity:** $O(1)$ — Constant extra storage.
  - **Overflow Risk:** For extremely large $N$ in 32-bit systems, $n(n + 1)$ can potentially overflow before division (avoided in JavaScript because numbers are 64-bit double precision floats up to $2^{53} - 1$).
