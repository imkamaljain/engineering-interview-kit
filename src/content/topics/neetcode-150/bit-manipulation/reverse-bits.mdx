## Problem Statement

Reverse the bits of a given 32-bit unsigned integer.

**Example 1:**
```text
Input: n = 00000010100101000001111010011100
Output: 964176192 (00111001011110000010100101000000)
Explanation: 
The input binary string represents the integer 43261596.
Reversing the sequence of 32 bits yields 00111001011110000010100101000000, 
which represents the integer 964176192.
```

**Example 2:**
```text
Input: n = 11111111111111111111111111111101
Output: 3221225471 (10111111111111111111111111111111)
Explanation: 
The input binary string represents the unsigned integer 4294967293.
Reversing its 32 bits yields 3221225471.
```

**Constraints:**
- The input must be a 32-bit integer.

**Follow up:**
If this function is called many times, how would you optimize it?


## Approach 1: 32-Step Bit Shifting

This problem directly assesses bit manipulation mechanics. We build the reversed number bit by bit:

1. Initialize `result = 0`.
2. Loop exactly **32 times** (once for each bit in a 32-bit integer):
   - **Extract:** Grab the rightmost bit of `n` using bitwise AND: `const bit = n & 1`.
   - **Shift Left:** Shift `result` to the left by 1 position (`result = (result << 1) | bit`) to make room on the right and insert the extracted bit.
   - **Shift Source Right:** Shift `n` to the right using the **unsigned right shift** (`n = n >>> 1`) to position the next bit for the next iteration.
3. **The JavaScript Unsigned Cast:** In JavaScript, bitwise operators operate on signed 32-bit integers. If the highest bit (bit 31) becomes `1`, JavaScript treats `result` as a negative number. Using `result >>> 0` forces JavaScript to treat it as an unsigned 32-bit integer.

## Solution

```javascript
/**
 * @param {number} n - a positive integer
 * @return {number} - a positive integer
 */
var reverseBits = function(n) {
    let result = 0;
    
    for (let i = 0; i < 32; i++) {
        // Extract rightmost bit from n, shift result left, and insert bit
        result = (result << 1) | (n & 1);
        
        // Unsigned shift n to the right
        n = n >>> 1;
    }
    
    // Cast signed 32-bit result to unsigned 32-bit integer
    return result >>> 0;
};
```


## Approach 2: Divide and Conquer / Bitmask Swapping ($O(1)$)

Instead of looping 32 times, we can reverse the bits using **divide and conquer** bitmask swaps in just 5 operations (similar to how merge sort divides an array):

1. Swap adjacent 16-bit halves.
2. Swap adjacent 8-bit bytes.
3. Swap adjacent 4-bit nibbles.
4. Swap adjacent 2-bit pairs.
5. Swap adjacent 1-bit pairs.

```javascript
/**
 * @param {number} n
 * @return {number}
 */
var reverseBitsFast = function(n) {
    // Swap 16-bit blocks
    n = ((n & 0xffff0000) >>> 16) | ((n & 0x0000ffff) << 16);
    // Swap 8-bit blocks
    n = ((n & 0xff00ff00) >>> 8)  | ((n & 0x00ff00ff) << 8);
    // Swap 4-bit nibbles
    n = ((n & 0xf0f0f0f0) >>> 4)  | ((n & 0x0f0f0f0f) << 4);
    // Swap 2-bit pairs
    n = ((n & 0xcccccccc) >>> 2)  | ((n & 0x33333333) << 2);
    // Swap odd/even individual bits
    n = ((n & 0xaaaaaaaa) >>> 1)  | ((n & 0x55555555) << 1);

    return n >>> 0;
};
```


## Follow-up: Byte-by-Byte Lookup Table

If `reverseBits` is called billions of times in high-frequency trading or embedded network drivers:
- Precompute an 8-bit lookup table `table[256]` mapping each byte `0-255` to its 8-bit reversed mirror.
- Reverse any 32-bit integer with 4 array lookups:
  $$\text{result} = (\text{table}[b_0] \ll 24) \ | \ (\text{table}[b_1] \ll 16) \ | \ (\text{table}[b_2] \ll 8) \ | \ \text{table}[b_3]$$


## Complexity Analysis

- **Time Complexity:** $O(1)$
  - Standard loop always performs exactly 32 iterations regardless of input value.
  - Divide-and-conquer approach runs in exactly 5 bitwise instructions.
- **Space Complexity:** $O(1)$
  - Only uses a few primitive variables in memory.
