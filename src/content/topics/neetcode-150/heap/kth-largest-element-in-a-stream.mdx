## Problem Statement

Design a class to find the `k`th largest element in a stream. Note that it is the `k`th largest element in the sorted order, not the `k`th distinct element.

Implement `KthLargest` class:
- `KthLargest(int k, int[] nums)` Initializes the object with the integer `k` and the stream of integers `nums`.
- `int add(int val)` Appends the integer `val` to the stream and returns the element representing the `k`th largest element in the stream.

**Example:**
```text
Input:
["KthLargest", "add", "add", "add", "add", "add"]
[[3, [4, 5, 8, 2]], [3], [5], [10], [9], [4]]

Output:
[null, 4, 5, 5, 8, 8]

Explanation:
KthLargest kthLargest = new KthLargest(3, [4, 5, 8, 2]);
kthLargest.add(3);  // return 4
kthLargest.add(5);  // return 5
kthLargest.add(10); // return 5
kthLargest.add(9);  // return 8
kthLargest.add(4);  // return 8
```

## Approach: Min-Heap (Size K)

When a problem asks for the "Kth Largest" or "Kth Smallest" element in a continuously changing dataset, your brain should immediately jump to **Heaps / Priority Queues**.

To find the `k`th largest element, we actually want to use a **Min-Heap**. Why? 
If we restrict our Min-Heap to hold *exactly* `k` elements, it will naturally hold the `k` largest elements we have ever seen. Because it is a Min-Heap, the *smallest* element out of those top `k` champions will always be sitting right at the top (the root). That root node is exactly the `k`th largest element!

**The Algorithm:**
1. Initialize a Min-Heap.
2. For every number in `nums`, add it to the heap.
3. If the heap's size ever exceeds `k`, pop the top element (discarding the smallest number).
4. For every `add(val)` call, push the new value into the heap. If the size exceeds `k`, pop.
5. Return the root (top) of the heap.

## Solution

*JavaScript Caveat: JS does not have a built-in Heap class natively in the browser/Node, but LeetCode provides the `@datastructures-js/priority-queue` library by default. In a real interview, you can usually assume this library exists, or you may be asked to quickly implement a basic `MinHeap` array class.*

```javascript
class KthLargest {
    /**
     * @param {number} k
     * @param {number[]} nums
     */
    constructor(k, nums) {
        this.k = k;
        // LeetCode's built-in Priority Queue
        this.minHeap = new MinPriorityQueue();
        
        // Initialize the heap with the starting numbers
        for (const num of nums) {
            this.add(num);
        }
    }

    /**
     * @param {number} val
     * @return {number}
     */
    add(val) {
        // Push the new value into the Min-Heap
        this.minHeap.enqueue(val);
        
        // If we have more than 'k' elements, kick out the smallest one
        if (this.minHeap.size() > this.k) {
            this.minHeap.dequeue();
        }
        
        // The top of the Min-Heap is exactly the kth largest element!
        return this.minHeap.front();
    }
}
```

## Complexity Analysis

- **Time Complexity:** 
  - **Initialization:** $O(N \log K)$ where $N$ is the initial size of `nums`. We add each element, and maintaining a heap of size $K$ takes $O(\log K)$ time per insertion.
  - **Add Operation:** $O(\log K)$. Pushing to a heap of size $K$ and popping takes logarithmic time.
- **Space Complexity:** $O(K)$. Our Min-Heap never holds more than exactly $K$ elements at any given time, making it incredibly memory efficient even for infinite streams!
