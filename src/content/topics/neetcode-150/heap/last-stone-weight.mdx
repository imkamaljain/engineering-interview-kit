## Problem Statement

You are given an array of integers `stones` where `stones[i]` is the weight of the $i^{\text{th}}$ stone.

We are playing a game with the stones. On each turn, we choose the heaviest two stones and smash them together. Suppose the heaviest two stones have weights `x` and `y` with `x <= y`. The result of this smash is:
- If `x == y`, both stones are destroyed.
- If `x != y`, the stone of weight `x` is destroyed, and the stone of weight `y` has new weight `y - x`.

At the end of the game, there is at most one stone left.

Return the weight of the last remaining stone. If there are no stones left, return `0`.

**Example 1:**
```text
Input: stones = [2,7,4,1,8,1]
Output: 1
Explanation: 
We combine 7 and 8 to get 1 so the array converts to [2,4,1,1,1] then,
we combine 2 and 4 to get 2 so the array converts to [2,1,1,1] then,
we combine 2 and 1 to get 1 so the array converts to [1,1,1] then,
we combine 1 and 1 to get 0 so the array converts to [1] then that's the value of the last stone.
```

**Example 2:**
```text
Input: stones = [1]
Output: 1
```

## Approach: Max-Heap (Priority Queue)

Because every single turn requires finding and removing the **two heaviest stones**, a **Max-Heap** is the ideal data structure:

1. **Why not repeatedly sort?**
   Sorting the array on every round would take $O(N \log N)$ per turn, leading to an inefficient $O(N^2 \log N)$ overall. Even with binary search insertion, it takes $O(N^2)$ due to array shifting.
2. **Max-Heap advantage:**
   - Extracting the maximum element takes $O(\log N)$ time.
   - Inserting the remaining weight $(y - x)$ takes $O(\log N)$ time.
   - We perform at most $N - 1$ smashes, yielding an optimal overall time complexity of $O(N \log N)$.

**The Algorithm:**
1. Insert all stone weights into a Max-Heap.
2. Loop while the heap contains more than 1 stone:
   - Extract the heaviest stone $y$.
   - Extract the second heaviest stone $x$.
   - If $y > x$, insert the difference $(y - x)$ back into the heap.
3. If the heap is not empty, return the single remaining stone. If it is empty, return `0`.

## Solution

*JavaScript Caveat: JavaScript does not have a native PriorityQueue in its standard library. On LeetCode, `@datastructures-js/priority-queue` is pre-imported and provides `MaxPriorityQueue`.*

```javascript
/**
 * @param {number[]} stones
 * @return {number}
 */
var lastStoneWeight = function(stones) {
    // LeetCode's built-in MaxPriorityQueue
    const maxHeap = new MaxPriorityQueue();
    
    // 1. Add all stones to the Max-Heap
    for (const stone of stones) {
        maxHeap.enqueue(stone);
    }
    
    // 2. Smash stones while at least two stones exist
    while (maxHeap.size() > 1) {
        const y = maxHeap.dequeue(); // Heaviest stone
        const x = maxHeap.dequeue(); // Second heaviest stone
        
        // If they are not equal, push the difference back
        if (y !== x) {
            maxHeap.enqueue(y - x);
        }
    }
    
    // 3. Return the remaining stone, or 0 if none remain
    return maxHeap.isEmpty() ? 0 : maxHeap.front();
};
```

## Complexity Analysis

- **Time Complexity:** $O(N \log N)$
  - Building the heap takes $O(N \log N)$ (or $O(N)$ with bottom-up heapify).
  - In each round, at least one stone is completely eliminated (either one destroyed and one modified, or both destroyed). Thus, there are at most $N - 1$ rounds.
  - In each round, we do at most 2 `dequeue` operations and 1 `enqueue` operation, each taking $O(\log N)$ time.
  - Total time: $O(N \log N)$.
- **Space Complexity:** $O(N)$
  - The heap stores up to $N$ elements simultaneously.
