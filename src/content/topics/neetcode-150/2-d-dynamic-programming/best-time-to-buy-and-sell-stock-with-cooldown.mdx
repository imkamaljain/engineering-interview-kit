## Problem Statement

You are given an integer array `prices` where `prices[i]` is the price of a given stock on the $i^{\text{th}}$ day.

Find the maximum profit you can achieve. You may complete as many transactions as you like (i.e., buy one and sell one share of the stock multiple times) with the following restrictions:

- After you sell your stock, you cannot buy stock on the next day (i.e., **cooldown of one day**).
- You may not engage in multiple transactions simultaneously (i.e., you must sell the stock before you buy again).

**Example 1:**
```text
Input: prices = [1,2,3,0,2]
Output: 3
Explanation: transactions = [buy, sell, cooldown, buy, sell]
Day 0: Buy at 1 (balance = -1)
Day 1: Sell at 2 (profit = 1) -> cooldown Day 2
Day 3: Buy at 0 (balance = 1)
Day 4: Sell at 2 (balance = 1 + 2 = 3)
```

**Example 2:**
```text
Input: prices = [1]
Output: 0
```

**Constraints:**
- `1 <= prices.length <= 5000`
- `0 <= prices[i] <= 1000`


## Finite State Machine Formulation

On any given day, an investor must be in exactly one of **three distinct states**:

1. **Hold (`hold`)**:
   - Currently holding a share of stock.
   - Can transition by **holding** (doing nothing) or by **selling** today.
2. **Sold (`sold`)**:
   - Just sold a share today.
   - Triggers the mandatory **cooldown** constraint for the next day.
3. **Rest / Cooldown (`rest`)**:
   - Holding 0 shares and free to buy today (either was resting yesterday or cooling down after selling).
   - Can transition by **buying** today or continuing to **rest**.

### State Transitions

For each day $i$ with stock price $P$:

$$
\begin{aligned}
\text{hold}[i] &= \max(\text{hold}[i - 1],\; \text{rest}[i - 1] - P) \\
\text{sold}[i] &= \text{hold}[i - 1] + P \\
\text{rest}[i] &= \max(\text{rest}[i - 1],\; \text{sold}[i - 1])
\end{aligned}
$$

### Base Cases (Day 0)

- $\text{hold}[0] = -P_0$ (buying the stock on day 0)
- $\text{sold}[0] = -\infty$ (cannot sell without holding first)
- $\text{rest}[0] = 0$ (starting with zero profit and 0 shares)

At the end of all days, maximum profit cannot be achieved while still holding stock, so the answer is:
$$\max(\text{sold}[n - 1],\; \text{rest}[n - 1])$$

## Solution 1: State Machine with $O(1)$ Space (Recommended)

Since each day's values depend solely on the previous day's states, we only need three scalar variables:

```javascript
/**
 * @param {number[]} prices
 * @return {number}
 */
var maxProfit = function(prices) {
    if (prices.length <= 1) return 0;

    let hold = -prices[0];
    let sold = -Infinity;
    let rest = 0;

    for (let i = 1; i < prices.length; i++) {
        const prevHold = hold;
        const prevSold = sold;
        const prevRest = rest;

        // 1. Keep holding or buy after resting
        hold = Math.max(prevHold, prevRest - prices[i]);

        // 2. Sell current holding
        sold = prevHold + prices[i];

        // 3. Keep resting or enter rest after yesterday's sale
        rest = Math.max(prevRest, prevSold);
    }

    return Math.max(sold, rest);
};
```


## Solution 2: Tabular 2D DP ($O(N)$ Time, $O(N)$ Space)

An explicit table storing each day's values for easier inspection and path reconstruction:

```javascript
/**
 * @param {number[]} prices
 * @return {number}
 */
var maxProfitTabular = function(prices) {
    const n = prices.length;
    if (n <= 1) return 0;

    // dp[i][0] = hold, dp[i][1] = sold, dp[i][2] = rest
    const dp = Array.from({ length: n }, () => new Int32Array(3));

    dp[0][0] = -prices[0];
    dp[0][1] = -1e9;
    dp[0][2] = 0;

    for (let i = 1; i < n; i++) {
        const p = prices[i];
        dp[i][0] = Math.max(dp[i - 1][0], dp[i - 1][2] - p);
        dp[i][1] = dp[i - 1][0] + p;
        dp[i][2] = Math.max(dp[i - 1][2], dp[i - 1][1]);
    }

    return Math.max(dp[n - 1][1], dp[n - 1][2]);
};
```


## Solution 3: Top-Down Recursion with Memoization

A recursive DFS model exploring the choice of buying/selling while respecting the cooldown jump (`i + 2` on sell):

```javascript
/**
 * @param {number[]} prices
 * @return {number}
 */
var maxProfitMemo = function(prices) {
    // memo[i][buying] stores max profit starting at index i with buying state (1 = can buy, 0 = must sell)
    const memo = new Map();

    const dfs = (i, buying) => {
        if (i >= prices.length) return 0;

        const key = (i << 1) | (buying ? 1 : 0);
        if (memo.has(key)) return memo.get(key);

        let profit = 0;
        if (buying) {
            // Option 1: Buy today (next state is selling, index advances by 1)
            const buy = dfs(i + 1, false) - prices[i];
            // Option 2: Cooldown / Skip today
            const cooldown = dfs(i + 1, true);
            profit = Math.max(buy, cooldown);
        } else {
            // Option 1: Sell today (mandatory cooldown skips to i + 2, next state is buying)
            const sell = dfs(i + 2, true) + prices[i];
            // Option 2: Cooldown / Keep holding
            const cooldown = dfs(i + 1, false);
            profit = Math.max(sell, cooldown);
        }

        memo.set(key, profit);
        return profit;
    };

    return dfs(0, true);
};
```


## Complexity Analysis

| Approach | Time Complexity | Space Complexity | Notes |
| :--- | :--- | :--- | :--- |
| **State Machine ($O(1)$ Space)** | $O(N)$ | $O(1)$ | Optimal. Only 3 state variables maintained in a single pass. |
| **Tabular DP ($O(N)$ Space)** | $O(N)$ | $O(N)$ | Explicit matrix representation; helpful for debugging transitions. |
| **Top-Down Memoization** | $O(N)$ | $O(N)$ | Call stack depth $O(N)$ with $2N$ distinct states cached. |


## Edge Cases

- **Single Day (`prices = [1]`):** Cannot complete any transactions; returns `0`.
- **Monotonically Decreasing (`prices = [5, 4, 3, 2, 1]`):** Every purchase yields a loss; optimal decision is to rest throughout, returning `0`.
- **Strictly Increasing (`prices = [1, 2, 4, 7]`):** Cooldown is irrelevant because holding continuously from day 0 to the final day and selling once produces maximal profit $7 - 1 = 6$.
- **Alternating Peaks and Valleys (`prices = [1, 2, 3, 0, 2]`):** Cooldown directly influences which valley to buy at.
