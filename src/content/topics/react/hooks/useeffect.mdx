## useEffect

`useEffect` is a React Hook that lets you synchronize a component with an external system. Some components need to stay connected to the network, some browser API, or a third-party library, while they are displayed on the page. These connections are called **Effects**.

### Syntax

```jsx
useEffect(setup, dependencies?)
```

- **`setup`**: The function with your Effect's logic. It may optionally return a cleanup function.
- **`dependencies`**: An optional array of reactive values (props, state, and variables/functions declared inside the component) referenced inside the `setup` code.

### The Dependency Array

The dependency array controls **when** the Effect runs.

1. **No dependency array:** The Effect runs after **every single render**.
   ```jsx
   useEffect(() => { /* Runs after every render */ });
   ```
2. **An empty dependency array `[]`:** The Effect runs **only once** after the initial render (mounting).
   ```jsx
   useEffect(() => { /* Runs only on mount */ }, []);
   ```
3. **Array with dependencies `[dep1, dep2]`:** The Effect runs on the initial render, and **re-runs only if any of the dependencies have changed** since the last render.
   ```jsx
   useEffect(() => { /* Runs if userId changes */ }, [userId]);
   ```

### The Cleanup Function

Some Effects require cleanup to reduce memory leaks (e.g., clearing timeouts, unsubscribing from WebSockets, removing event listeners). If your `setup` function returns a function, React will use it as a cleanup function.

React calls the cleanup function:
1. Before the Effect runs again (due to a dependency change) to clean up the previous render's Effect.
2. When the component unmounts (is removed from the screen).

```jsx
useEffect(() => {
  const connection = createConnection(serverUrl, roomId);
  connection.connect();

  // Cleanup function
  return () => {
    connection.disconnect();
  };
}, [serverUrl, roomId]);
```

### When NOT to use useEffect

You do **not** need `useEffect` to transform data for rendering. If you can calculate a value from existing props or state, just calculate it during rendering. 

You do **not** need `useEffect` to handle user events. Use event handlers (like `onClick`) for that. Effects are specifically for code that should run because the component was displayed or updated on the screen, not because of a specific interaction.


## Interview Questions

**Q: What is the purpose of the dependency array `[]` in `useEffect`?**
**A:** It tells React exactly when to re-run the effect. If omitted, the effect runs after *every* render. If empty `[]`, it runs only once on mount. If it contains variables `[a, b]`, it runs only when `a` or `b` changes.

**Q: What happens if you open a WebSocket inside `useEffect` but forget to return a cleanup function?**
**A:** You will cause a massive memory leak. Every time the component re-renders or mounts, a brand new WebSocket connection will be opened, and the old ones will stay alive in the background indefinitely.
