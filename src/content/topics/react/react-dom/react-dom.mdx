## React DOM

`react-dom` is the package that provides DOM-specific methods that can be used at the top level of your web app to enable an efficient way of managing DOM elements of the web page.

While the `react` package itself contains the core algorithms for component state, hooks, and the Virtual DOM reconciliation engine, `react-dom` is the "renderer" that actually takes that Virtual DOM and translates it into physical HTML elements in a web browser.

### Why is it a separate package?

React was split into two packages (`react` and `react-dom`) in version 0.14. 

This separation is what makes React so powerful and versatile. Because the core `react` library knows absolutely nothing about the browser or HTML, it can be paired with *other* renderers to build applications for entirely different platforms using the exact same component logic:

- **React Native:** Uses the `react-native` renderer to translate React components into native iOS and Android UI elements.
- **React 360:** Renders UI into 3D and VR spaces.
- **Ink:** Renders React components into the terminal (command-line interfaces).
- **React Three Fiber:** Renders React components into Three.js canvases.

### Primary Responsibilities of `react-dom`

1. **Mounting:** Injecting the initial React application into a physical HTML element (usually `<div id="root"></div>`) via `createRoot()`.
2. **Updating:** Applying the minimum necessary DOM mutations (calculated by the React reconciler) to the browser's DOM.
3. **Event Handling:** React DOM implements a synthetic event system (which abstracts away cross-browser differences) and attaches it to the document using Event Delegation.
4. **Portals:** Providing `createPortal()` to render children into a different part of the DOM tree.

### Client vs Server

The `react-dom` package is actually divided into two main entry points in modern React:
- `react-dom/client`: Methods for rendering on the client (browser), like `createRoot` and `hydrateRoot`.
- `react-dom/server`: Methods for rendering React components to static HTML strings on a Node.js server (e.g., `renderToString`, `renderToPipeableStream`).
