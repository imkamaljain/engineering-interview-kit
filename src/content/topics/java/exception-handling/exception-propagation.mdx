## TL;DR

- **Exception Propagation** is the process where an unhandled exception moves backward through the method call stack.
- If Method C throws an exception, it drops down to Method B. If B doesn't handle it, it drops to Method A, and so on until it is caught or reaches the JVM.
- **Unchecked exceptions** propagate automatically.
- **Checked exceptions** only propagate if every method in the chain explicitly declares `throws`.

## Concept

Think of the Call Stack as a stack of plates. `main()` is on the bottom, calling `methodA()`, which calls `methodB()`, which calls `methodC()`. 
If `methodC()` throws an exception and has no `catch` block, Java removes `methodC()` from the stack and hands the exception down to `methodB()`. This continues until a matching `catch` block is found. 

This mechanism allows you to centralize error handling. Instead of writing `try-catch` blocks in 50 different helper methods, you can just let the exceptions propagate up to the top level (like a web controller) and handle them all in one place.

## Examples

```java
public class ExceptionPropagation {

    public static void methodC() {
        System.out.println("Inside C: about to divide by zero.");
        // Throws ArithmeticException (Unchecked)
        int x = 10 / 0; 
        System.out.println("This won't print.");
    }

    public static void methodB() {
        System.out.println("Inside B: calling C.");
        methodC(); // Exception propagates down to B
        System.out.println("This won't print.");
    }

    public static void methodA() {
        System.out.println("Inside A: calling B.");
        try {
            methodB(); // Exception propagates down to A and is caught!
        } catch (ArithmeticException e) {
            System.out.println("A caught the exception! " + e.getMessage());
        }
    }

    public static void main(String[] args) {
        System.out.println("Main started.");
        methodA();
        System.out.println("Main finished gracefully.");
    }
}
```

## Interview Questions

Q: Can checked exceptions propagate automatically?
A: No. If `methodC()` throws a checked exception (like `IOException`), the compiler will give a compilation error unless `methodC()` handles it OR adds `throws IOException` to its signature. For it to propagate to `methodA()`, *both* `methodC()` and `methodB()` must declare `throws IOException`. Unchecked exceptions, on the other hand, propagate silently without any `throws` declarations.

Q: What is the "Stack Trace"?
A: The Stack Trace is a textual representation of the call stack at the exact moment the exception was thrown. When an exception propagates all the way up and crashes the program, the JVM prints the stack trace, showing the file names and line numbers of `methodC`, `methodB`, `methodA`, and `main`, allowing developers to trace exactly how the program reached the erroneous code.
