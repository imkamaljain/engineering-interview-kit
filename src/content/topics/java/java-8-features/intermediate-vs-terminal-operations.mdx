## TL;DR

- **Intermediate Operations** return a new `Stream`. They are lazy and do not execute until a terminal operation is invoked. (e.g., `filter`, `map`, `sorted`).
- **Terminal Operations** produce a non-stream result (like a `List`, `int`, or `void`) and mark the end of the stream pipeline. (e.g., `collect`, `count`, `forEach`).

## Concept

When you work with Java Streams, you are building a recipe (a pipeline). 

### Intermediate Operations
When you call `stream.filter(...)`, Java doesn't actually loop through the list and filter anything yet. It simply remembers that you *want* to filter it. Because intermediate operations return a `Stream`, you can chain as many of them together as you want: `stream.filter().map().distinct().sorted()`.

### Terminal Operations
The recipe is only executed when you call a Terminal Operation (like `collect()` or `findFirst()`). This triggers the **lazy evaluation**. Java optimizes the pipeline and pulls data from the source, pushing it through the intermediate operations only as much as necessary to satisfy the terminal operation. Once a terminal operation finishes, the stream is closed and cannot be used again.

## Examples

```java
import java.util.List;
import java.util.stream.Stream;

public class StreamOpsExample {
    public static void main(String[] args) {
        
        List<String> names = List.of("Alice", "Bob", "Charlie", "David");
        
        // --- 1. Intermediate Operations (Lazy) ---
        Stream<String> intermediateStream = names.stream()
            .filter(name -> {
                System.out.println("Filtering: " + name); // Won't print yet!
                return name.length() > 3;
            })
            .map(String::toUpperCase);
            
        System.out.println("Pipeline built. Executing terminal operation...");
        
        // --- 2. Terminal Operation (Triggers execution) ---
        long count = intermediateStream.count();
        System.out.println("Total long names: " + count);
        
        // If we try to use intermediateStream again, we get an Exception:
        // intermediateStream.forEach(System.out::println); // ERROR!
    }
}
```

## Interview Questions

Q: What does "Short-Circuiting" mean in the context of Streams?
A: Short-circuiting happens when a terminal operation does not need to process all the elements to return a result. For example, if you have a stream of 1 million items and call `.findFirst()`, the stream will only pull *one* item through the pipeline (e.g., through the `filter` and `map` operations). Once it finds the first match, it stops processing the rest of the 999,999 items, saving massive amounts of compute time.

Q: Can you have a Stream pipeline with no Intermediate Operations?
A: Yes, absolutely. You can write `list.stream().count();`. The intermediate operations are entirely optional. However, every valid stream pipeline *must* have exactly one Terminal Operation to actually execute.
