## TL;DR

- **Generics** enable types (classes and interfaces) to be parameters when defining classes, interfaces, and methods.
- They provide **compile-time type safety**, eliminating `ClassCastException` at runtime.
- They allow developers to write reusable code that can work with any object type.

## Concept

Before Generics were introduced in Java 5, collections stored standard `Object`s. When you retrieved an item from a list, you had to cast it back to its original type. If you accidentally put an `Integer` into a list you thought was for `String`s, the compiler wouldn't care, but your program would crash at runtime.

Generics solve this by allowing you to enforce the type parameter at compile time using angle brackets `<T>`.

### Benefits
1. **Stronger Type Checks at Compile Time:** The compiler catches type mismatch errors.
2. **Elimination of Casts:** You don't need to write `(String) list.get(0)`.
3. **Generic Algorithms:** You can write algorithms that work on collections of different types while remaining type-safe.

## Examples

```java
import java.util.ArrayList;
import java.util.List;

public class GenericsExample {
    public static void main(String[] args) {
        
        // --- BEFORE GENERICS (Java 1.4 and earlier) ---
        List oldList = new ArrayList();
        oldList.add("Apple");
        oldList.add(100); // The compiler allows this!
        
        // Requires casting. Will throw ClassCastException at runtime
        // when it hits the Integer!
        // String fruit = (String) oldList.get(1); 
        
        // --- WITH GENERICS (Java 5+) ---
        List<String> newList = new ArrayList<>();
        newList.add("Apple");
        
        // newList.add(100); // COMPILE-TIME ERROR! (This is good)
        
        // No casting required
        String newFruit = newList.get(0); 
    }
}
```

## Interview Questions

Q: Can you use primitive types with Generics?
A: No. You cannot write `List<int>`. Generics in Java only work with Reference Types (Objects). To use primitives, you must use their corresponding Wrapper classes, like `List<Integer>`. Java's autoboxing will automatically convert `int` primitives to `Integer` objects for you.

Q: What is the "Diamond Operator"?
A: Introduced in Java 7, the diamond operator `<>` allows you to omit the type parameter on the right side of an assignment if the compiler can infer it from the left side. 
Instead of writing `List<String> list = new ArrayList<String>();`, you simply write `List<String> list = new ArrayList<>();`.
